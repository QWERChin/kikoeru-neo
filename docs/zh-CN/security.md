# 安全与网络边界

部署时先决定谁能访问应用、后端能读取哪些目录和远端服务，再配置监听与 HTTPS。应用要求登录，但管理员能配置本地路径和内网地址，登录本身不是主机或网络隔离机制。

## 选择访问入口

默认监听 `127.0.0.1:8888`，适合本机浏览器、SSH 转发或同机反向代理。只在可信局域网内直接访问时，可以在配置中设置：

```toml
listen = "0.0.0.0:8888"
```

这会监听所有 IPv4 接口，需要自己用防火墙限制来源。更窄的选择是填服务器具体的接口 IP。Docker 示例只把端口发布到宿主机回环地址，不代表容器内部也监听回环。

来自不可信网络的访问应通过 HTTPS 反向代理，并为入口设置请求超时和连接数限制。应用本身没有完整的入口连接限额。NixOS 模块不配置证书、DNS、代理或防火墙，`public_url` 也不负责这些工作。

## 配置一层反向代理

1. 让代理终止 HTTPS，转发应用页面、`/api` 和媒体请求。使用独立站点根路径，不假定应用支持任意路径前缀。
2. 限制后端只允许代理访问，防止客户端绕过代理提交伪造的来源头。
3. 代理写入实际客户端的 `X-Forwarded-For`，并在 `trusted_proxies` 中只填写后端看到的代理 IP。
4. 代理保留 Range、Content-Range 和流式传输行为，不缓存登录或其他 `no-store` API 响应，不缓冲任务事件流。访问日志去掉 `token` 查询参数，或不记录查询串。
5. 从客户端登录并查看服务日志，确认记录的来源符合预期，再检查播放拖动和任务进度。

同机代理通过 IPv4 回环访问后端时，可以使用：

```toml
listen = "127.0.0.1:8888"
trusted_proxies = ["127.0.0.1"]
```

这还信任了能够从本机回环连接的其他进程，只适用于本机进程也可信的部署。代理若通过 `::1` 连接，应配置实际地址，不是照抄 IPv4 示例。

`trusted_proxies` 接受单个 IP，不接受 CIDR 网段。默认空列表只看 TCP 对端地址。只有对端在列表中时，服务才使用 `X-Forwarded-For` 的最后一项，前面的项不作为可信客户端地址。当前只支持这一层代理模型，多层代理不能只靠把所有代理 IP 加进去获得正确的来源链。

Docker 中后端看到的来源取决于网络模式和转发方式，不一定是网桥网关。若直接客户端和代理都被映射成同一地址，不能信任这个地址提供的任意来源头。保留后端端口隔离，并实际检查日志，不在默认 Compose 中预填网关为可信代理。

## 纯 HTTP 能做什么

局域网 HTTP 支持登录、浏览、收藏、播放、进度和管理功能。浏览器只有在 HTTPS 或认可的本机安全上下文下才提供 Service Worker，因此普通局域网 HTTP 不能提供相应的 PWA 安装和离线打开功能。后台播放和媒体控制还受系统及浏览器影响，不能简单归结为“没有 HTTPS”。

HTTP 不加密密码、API token、媒体 token 和内容，网络中的攻击者可能读取或修改它们。需要跨不可信网络时使用 HTTPS，不把整个局域网或共享 Wi-Fi 自动视为可信。

## 远端存储和代理凭据

OpenList 和 WebDAV 文件由后端取回再转发给浏览器，浏览器不会直接拿到 OpenList 直链。OpenList 账号必须是管理员且基础路径为 `/`，因此应保护它的凭据和后端数据目录。WebDAV 每次请求携带 Basic 凭据，HTTP 传输不能保护密码。

存储客户端使用编译进二进制的公共 CA 根证书，不读取系统自定义 CA。给容器挂载自签 CA 文件不能让 OpenList 或 WebDAV 自动信任它。需要 HTTPS 时使用受支持的证书链，不关闭证书校验。PostgreSQL 的证书配置是另一条路径，可通过 `sslrootcert` 指定，见[配置](configuration.md)。

文件配置引用 `password_file`，网页添加的密码保存为数据目录中 `secrets/roots/<id>.password`。Nix store 可被本机用户读取，不能把密码写进 NixOS `settings`。备份包含这些密码，保护范围应与数据目录相同。

WebDAV 和元数据客户端会使用进程环境中的 HTTP 代理设置，OpenList 客户端不使用它们。只想让元数据走代理时，用设置页的“网络代理”，它覆盖元数据客户端的环境选择，不影响 WebDAV。不要把本机代理地址误填成远程服务器可用的地址。

## 账号和权限限制

所有登录用户都能浏览媒体库，当前没有按用户隐藏作品或媒体库的权限机制。只把管理员权限交给可以信任其选择后端可读目录和网络地址的人。本地文件不跟随符号链接，但服务账号仍应只拥有所需权限。

API token 有效 30 天，媒体 token 有效 6 小时。修改密码或“退出所有设备”立即撤销该用户已有 token，删除用户也使其 token 失效。怀疑凭据泄露时使用这些操作，并检查保存过 token 的代理日志和备份，见[账号](accounts.md)。

登录地址限流按当前和上一分钟窗口累计，达到 10 次失败后暂时拒绝该地址。反向代理配置错误或多个用户共用 NAT 会共享这个限制。它不能代替强密码、HTTPS 或入口防护。

远端存储地址和 OpenList 返回的直链仍可能访问局域网资源，管理员和远端服务属于信任边界。需要更严格的隔离时，用独立运行账号、容器网络或防火墙限制后端的出站访问。恢复演练必须另行隔离，见[备份与恢复](backup-restore.md)。
