# 按症状排查

先记录出现问题的版本、运行方式、操作步骤和错误原文，再检查服务日志。不要为了排障删除数据库、重建数据卷或清理缺失作品，先[备份](backup-restore.md)。日志和截图可能包含自己的路径、用户名、凭据或作品信息，分享前先脱敏。

## 找到日志

NixOS：

```sh
systemctl status kikoeru-neo
journalctl -u kikoeru-neo -n 100 --no-pager
```

Docker 在 Compose 目录运行：

```sh
docker compose ps
docker compose logs --tail 100 kikoeru-neo
```

直接运行时看终端 stderr。桌面本机模式在设置或启动错误页点“打开日志文件夹”，位置见[桌面应用](desktop.md)。每个任务结束的日志带任务 ID，方便与设置页对应。

## 页面打不开或容器不健康

1. 确认进程运行，日志没有配置解析或数据库迁移错误。
2. 在服务所在机器请求监听地址的 `/api/ready`，例如默认端口的 `http://127.0.0.1:8888/api/ready` 应返回 HTTP 200。
3. 本机正常、其他设备失败时，检查监听、防火墙、Docker 端口映射和反向代理。默认回环监听不会接受其他设备直接访问，`public_url` 不会改变它。

Docker 缺少 `/config/config.toml` 会启动失败。镜像的 `KIKOERU_LISTEN` 覆盖文件里的 `listen`，健康检查也读取它，清空该变量后必须同步调整健康检查。镜像没有 `/bin/sh`，不要使用依赖它的健康检查字符串，见[Docker 安装](install-docker.md)。

用普通 Cargo 构建的后端默认不嵌入网页，API 能访问而首页返回 JSON 404 时，改用包含前端的 Nix 服务端包。

## 创建了管理员，页面仍要求初始化

账号命令可能写进了另一数据库。检查 `--data-dir`、`KIKOERU_CONFIG`、`KIKOERU_DATABASE_URL` 与服务实际设置是否相同。Docker 里的 `serve --config` 不会自动传给另一次 `user` 命令，使用安装页的公共环境变量设置。NixOS 要用模块安装的命令并以服务用户运行。

旧库导入的账号没有密码，用[账号命令](accounts.md)重设。桌面本机模式应自动登录，异常进入登录页时完全退出再重开。

## 正确密码也被限流

同一来源地址的失败会累计，成功登录不会清掉之前的失败计数。达到地址限制后要等计数窗口过期，可能持续到约 2 分钟。反向代理或 NAT 后多个用户可能共用地址，检查日志中的客户端地址和 `trusted_proxies`，不要为绕过限流信任所有来源。用户名维度只减速，不直接封禁，见[安全与网络](security.md)。

## 服务拒绝数据目录权限

服务拒绝同组或其他用户可写的数据目录与 SQLite 文件。`secrets/` 和签名密钥也不能让其他用户读取，`jwt.key` 必须是普通文件。恢复后应使用服务属主、目录 `0700`、文件 `0600`。

Docker 的 NAS 数据卷、`0777` 挂载或 `fsGroup` 改写权限都可能触发检查。把应用数据放在能保持权限的本地文件系统，不放宽检查。媒体目录可只读挂载，它与保存数据库的数据目录不是同一用途。

## 媒体库不可用或扫描后没有作品

- 本地库先检查路径是否属于服务器或容器的视角，磁盘是否挂载，服务账号是否能列目录。空根目录也会报告不可用。
- 检查作品目录有 `RJ`、`BJ`、`VJ` 编号，媒体库指向它们的父目录，不依靠符号链接，见[目录规则](libraries.md#准备作品目录)。
- OpenList 确认使用管理员账号且账号基础路径为 `/`，密码文件可读，`base_path` 正确。能列目录不等于有 `fs/link` 播放权限。
- WebDAV 确认是实际 DAV 入口，不是网页登录页，Basic 凭据有效，服务没有跨来源重定向。
- 部分目录列出失败时扫描可能仍显示完成，结合任务日志核对，不把完成标记当作完整入库证明。

深层文件变化没出现时，可选“完整扫描（刷新网盘缓存）”重新遍历 OpenList 或 WebDAV 作品。这个选项不刷新 OpenList 缓存，OpenList 列表仍旧时先处理上游缓存。网络挂载收不到文件通知时，增加定时扫描而不只依赖 `watch`。

## 有轨道但没有封面、标题或时长

元数据失败不阻止入库，目录名和占位图是允许的结果。检查日志中的来源请求错误、`metadata.source` 是否为 `none`，以及设置页的元数据代理是否从后端可达。桌面应用不读取系统代理设置。

扫描完成不等于所有本地探测结束，远端音视频一般在首次播放时才探测。作品详情可以重新抓取元数据，但它不会重新扫描媒体文件。远端封面读取也受存储连接和限流影响。

## 播放失败、准备时间很长或 `queue_full`

先区分媒体库断线、浏览器不支持格式、后台任务排队和磁盘不足。检查设置页任务及日志，确认 ffmpeg、ffprobe 可运行。Nix 包和镜像已包含工具，单独复制一个二进制不会自动带齐它们。

`queue_full` 表示这一类任务（转码，或者响度和波形分析）的排队已达上限，等这类任务结束再试。磁盘低于 `cache.min_free_bytes` 时新的生成任务会被拒绝，释放无关空间或调整合理的缓存预算，不删除数据库或凭据。关闭 `media.video_transcode` 后，不支持直接播放或转封装的视频会明确失败。

代理需要正确转发 Range 请求和响应，不能缓存登录响应，也不要缓冲任务事件流。浏览器控制台的 CSP 或媒体错误可以帮助区分代理配置和播放器问题。后台、锁屏或系统媒体键失败要记录具体浏览器和系统，模拟器或桌面冒烟不证明这些功能，见[桌面验证范围](desktop.md#验证范围与限制)。

## 不能安装 PWA 或离线打开

普通局域网 HTTP 不是安全上下文，浏览器不会提供 Service Worker。登录和在线播放仍可用，安装及离线打开需要 HTTPS 或浏览器认可的本机来源。改用 HTTPS 后重新访问，但不要把安装成功当作已支持离线媒体下载，见[安全与网络](security.md)。

## 升级后无法启动

保留错误日志和当前数据。配置项非法时修正配置，schema 比程序更新时恢复匹配的软件，或按[备份与恢复](backup-restore.md)恢复旧备份。不要手动改迁移版本绕过检查。重启中断的扫描需在服务正常后重新提交。
