# 添加媒体库并扫描

媒体库是一组作品目录，可以来自本地文件系统、OpenList 或 WebDAV。管理员添加媒体库后需要扫描，资料库才会出现作品。本页说明目录准备、连接要求和扫描结果的判断。

## 准备作品目录

扫描器从媒体库根目录向下查找最多 16 层。目录名中出现 `RJ`、`BJ` 或 `VJ` 加 6 到 8 位数字时，该目录成为作品目录，不再向其中查找其他作品。编号大小写不敏感，前面不能紧挨英文字母，数字不能全为零。

以下是合成目录示例，实际使用自己作品的编号：

```text
/srv/media/works/
  RJ01234567 示例作品/
    01.wav
    特典/
      02.mp3
```

媒体库路径应是 `/srv/media/works`，不是单部作品目录。无编号目录只作为分类目录继续遍历，不会按其中的音频文件名创建作品。符号链接不会跟随。同一编号的多个位置会合并成一部作品，位置可以在作品详情页查看。

## 在网页添加

登录管理员账号，在“设置”中点“添加媒体库”。填写名称、类型和对应连接信息，检查生成的媒体库 ID，再保存。ID 用于链接和数据库，添加后不能修改。界面添加的媒体库保存在数据库，修改立即生效。

| 类型 | 准备条件 | 路径的含义 |
|---|---|---|
| 本地 | 服务运行账号可遍历目录并读取文件。 | 后端所在机器上的绝对路径，Docker 中是容器内挂载路径。 |
| OpenList | OpenList 管理员账号，账号的基础路径为 `/`。 | `base_path` 是 OpenList 中的媒体根目录。 |
| WebDAV | 支持 `PROPFIND` 和文件读取的 WebDAV 服务及 HTTP Basic 凭据。 | `url` 是 WebDAV 入口，`base_path` 是入口下面的媒体目录。 |

OpenList 的管理员要求来自播放使用的 `fs/link` 接口。普通账号即使能列目录，也不满足播放要求。OpenList 账号本身的基础路径 `/` 与 kikoeru-neo 媒体库的 `base_path` 是两回事，后者仍应指向所需作品目录。

WebDAV 只支持 Basic 认证，只跟随协议、主机和端口均不变的重定向，最多 5 次。需要网页表单登录或跨主机登录跳转的地址不能直接作为 WebDAV 入口。HTTP 和证书限制见[安全与网络](security.md)。

## 用文件声明媒体库

需要用配置管理维护媒体库时，在 `config.toml` 写 `[[roots]]`，或在 NixOS 的 `settings.roots` 写对应字段。文件声明的媒体库在网页里只读，改完需要重启。选择网页或文件维护同一个 ID，不要在两处重复定义。

```toml
[[roots]]
id = "local"
display_name = "本地作品"
type = "local"
path = "/srv/media/works"
watch = true
auto_scan_interval = "1d"
```

OpenList 示例中的地址、账号和路径需要换成自己的值。密码文件应由服务用户读取，不把密码直接写进 TOML：

```toml
[[roots]]
id = "cloud"
display_name = "云端作品"
type = "openlist"
url = "http://192.0.2.10:5244"
base_path = "/media/works"
username = "library-admin"
password_file = "/run/secrets/openlist-password"
list_concurrency = 4
link_rate = 1.0
auto_scan_interval = "6h"
```

`192.0.2.10` 仅代表自己的 OpenList 主机，不是可直接连接的服务器。这个 HTTP 示例只适用于可信网络。WebDAV 的对应示例是：

```toml
[[roots]]
id = "dav"
display_name = "WebDAV 作品"
type = "webdav"
url = "http://192.0.2.20:8080/dav"
base_path = "/media/works"
username = "library-reader"
password_file = "/run/secrets/webdav-password"
list_concurrency = 4
auto_scan_interval = "6h"
```

`url` 的路径和 `base_path` 会拼接，避免把 `/dav` 重复写两遍。两类远端的列目录并发默认是 4，OpenList 取直链速率默认是每秒 1 次。不要为缩短一次扫描盲目提高限额，远端可能限流。

配置中的 ID 只能包含 ASCII 字母、数字、`-` 和 `_`，不能为空。它不应随着显示名称或服务器地址变化。Docker 使用文件凭据时，还要把密码文件只读挂载到容器中相同的路径。

## 发起扫描并核对结果

1. 保存媒体库后，在它旁边点“扫描”，或用“扫描全部”。媒体库状态应能连通，任务应从排队进入运行。
2. 等待发现作品、同步轨道、抓取元数据和读取封面完成。跨媒体库也一次只运行一个扫描，同一媒体库重复提交会复用已有任务。
3. 打开资料库和作品详情，核对目录、轨道、封面及播放。扫描完成后本地时长探测可能仍在后台运行，远端音视频通常在第一次播放时探测。

页面离开只停止显示进度，扫描继续运行。需要停止时点“取消任务”。服务重启会把运行中的任务标为中断，需要重新发起扫描，排队任务会恢复排队。

设置页当前把开关标为“完整扫描（刷新网盘缓存）”。它实际上对 OpenList 和 WebDAV 关闭作品目录摘要跳过，让每部作品重新遍历，**不会刷新 OpenList 缓存**。远端深层变化没有反映在上层目录摘要里时可用它重新遍历，但 OpenList 自己还在返回旧列表时，需要先在 OpenList 侧处理缓存。自动扫描仍是普通扫描，不等同于完整扫描。

抓不到元数据不阻止作品入库和播放。作品先用目录名和占位封面，也可能从作品文件夹取得封面。恢复联网后可在详情页重新抓取。扫描会读取候选封面图片，不是只读取目录列表。

## 自动扫描与目录监听

服务器默认不开启自动扫描和本地目录监听。桌面本机模式默认监听本地目录变化。设置可以在媒体库编辑页修改，或用文件中的 `auto_scan_interval` 和 `watch` 声明。

| 设置 | 允许范围和行为 |
|---|---|
| 本地 `auto_scan_interval` | 最短 `5m`，最长 `30d`，不写则关闭。 |
| OpenList、WebDAV `auto_scan_interval` | 最短 `30m`，最长 `30d`，不写则关闭。 |
| 本地 `watch` | 变化停止 10 秒后排一次扫描。 |
| 远端 `watch` | 不支持，不能设成 `true`。 |

扫描间隔从上次扫描结束计算，失败和取消也算。没有扫描过的媒体库从启用自动扫描时开始计时，不会因为刚添加就立刻扫描。启动恢复实例时，旧扫描时间可能已经到期。

网络共享和 Docker Desktop 挂载不一定传递文件通知，显示正在监听也不能证明每次变化都能收到。对这类媒体库同时设置定时扫描，并手动核对一次新增文件是否出现。

## 缺失和其他限制

媒体库断线、权限不足等目录列出失败的情况，不会把已有作品标为缺失。空的本地根目录会报告不可用，放入第一部作品后再扫描。OpenList 或 WebDAV 成功返回空列表时则不同，可能把这个媒体库的全部位置标为缺失，远端目录被清空或换过位置之后，先确认它能列出作品再扫描。部分作品遍历失败时，已有轨道保留，但设置页仍可能显示整个扫描完成，详细扫描摘要目前不在任务接口中返回。发现缺项时结合日志检查，不能只看完成标记。

确认缺失的作品默认不显示，但收藏和进度保留。管理员在“缺失的作品和位置”中清理才删除数据库记录，清理作品也会删除其收藏、进度和封面，应先备份。删除媒体库不会删除原始媒体文件。恢复同一 ID 和路径后重新扫描，可以恢复仍存在的内容。
