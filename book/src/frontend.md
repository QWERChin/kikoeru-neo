# 前端设计

前端位于 `web/`，用同一份 SvelteKit 静态产物提供浏览器、PWA 和桌面应用界面。本章说明页面结构、播放状态、认证边界与平台差异。

## 发布方式

前端是一个单页应用（SPA）：

- 用 `adapter-static`，根布局设 `ssr = false`，`fallback: 'index.html'`。作品详情这类带 ID 的页面不在构建时预渲染。
- 生产环境里，前端产物嵌进后端二进制，部署在同一个域名的根路径下。后端对页面路径返回 `index.html`，对 `/api/*` 和不存在的静态资源返回真正的错误，不回退到 HTML。具体规则如下：
  - 路径以 `/api/` 开头或者就是 `/api`，没有对应的接口时返回 JSON 的 404 `not_found`。
  - 产物里有这个文件，就返回它，`Content-Type` 按扩展名决定。
  - 没有这个文件时，最后一段不带扩展名、并且不在 `/_app/` 下的路径算页面路径，返回 `index.html`。其他路径返回 JSON 的 404，这样过期的脚本块会明确地加载失败，而不是被当成 HTML 解析。
  - 页面路径只接受 GET 和 HEAD，其他方法返回 405。
  - `/_app/immutable/` 下的文件名带内容哈希，响应头是 `Cache-Control: public, max-age=31536000, immutable`。其余文件，包括 `index.html` 和 Service Worker，用 `no-cache`，每次加载都按 `ETag` 重新验证。
  - 请求的 `Accept-Encoding` 里有 gzip 时，页面、脚本、样式和 WebAssembly 压缩后再发。局域网里常常不加反向代理、直接用 HTTP 访问，这时没有别的地方压缩它们，压缩由服务端完成，减少前端文件的传输量。woff2 本身已经压缩过，SVG 以外的图片和 1 KiB 以下的响应也不压缩，这个门槛和接口的一样，所以回退路由给未知 `/api` 路径的 JSON 404 也不压缩。接口的 JSON 和文本由接口自己的规则压缩，见[接口合同](contract.md)的“通用规则”，媒体（包括音频的范围请求）照旧原样发送。同一个文件压缩和不压缩的两种形式共用一个弱 `ETag`（`W/"…"`），响应都带 `Vary: Accept-Encoding`。
- 生产构建不带 `VITE_API_MOCK`，假数据的代码块不会进入产物。Nix 的前端检查会在产物里找合同样本的内容，找到就失败。
- 开发时用 Vite 的开发服务器，把 `/api` 代理到 `http://127.0.0.1:8888`。
- 用的是 SvelteKit 3。它不再读 `svelte.config.js`，Kit 和适配器的配置都写在 `web/vite.config.ts` 里。`src/lib` 下的模块通过 `package.json` 的 `imports` 用 `#lib/...` 引用，取代旧的 `$lib` 别名。

构建顺序固定为：导出 DTO 类型 → 构建前端 → 构建后端并嵌入前端产物。导出类型的程序是一个独立的小二进制，不依赖已经嵌入前端的服务端。

## 设计语言

- **iOS 风格**：大标题、分组列表、半透明底栏，字体用系统字体（`-apple-system`、`PingFang SC`，回退到 `Noto Sans SC`）。很多 Linux 发行版装的思源黑体叫 `Noto Sans CJK SC`，所以它也排在回退列表里。不加载任何网络字体，拉丁字母和数字也用系统字体。
- **封面优先**：封面按 DLsite 常见的 4:3 比例显示，资料库和收藏页都用封面网格，不用列表。
- **强调色**：默认为 `#0a63c9`。红心固定为 `#ff2d55`。用户可以在设置里从八个命名颜色中换一个强调色（接口合同的 `Accent`），每个颜色在两种主题下的色值由前端定义，要满足和这里的蓝色同样的对比度要求。`#0a63c9` 在深色背景上作为文字时对比度不到 4.5:1，所以深色模式下用作文字和线条图标的强调色换成 `#5aa5f7`（CSS 变量 `--accent-text`）。按钮和选中项的底色仍然是 `#0a63c9`，上面的白字对比度足够。
- **深色模式**：默认跟随系统，也可以在设置里固定成浅色或深色，见下面的“主题”。颜色全部定义成 CSS 变量。

## 页面

| 页面 | 手机 | 桌面 |
|---|---|---|
| 资料库 | 大标题，“继续收听”大卡片，“最近添加”两列封面网格 | 左侧栏加封面网格，一行 5 到 6 个 |
| 搜索 | 搜索框加最近搜索，结果用封面网格 | 侧栏顶部的搜索框，结果在右侧 |
| 收藏 | 一个封面网格，按加入时间排序 | 同左，侧栏里有“收藏”入口 |
| 最近 | 按播放时间倒序，显示进度 | 同左 |
| 我的评价 | 评过分或写过短评的作品，封面网格，从设置页进入 | 同左，侧栏里有“我的评价”入口 |
| 作品详情 | 顶部大封面，标题、社团、声优、DLsite 评分，管理员还能看到所在位置，继续播放按钮，“收藏”和“标记为听过”，标签，曲目树和下载按钮 | 窗口够宽时封面在左、信息在右，曲目树在下方 |
| 全屏播放 | 大封面，进度条，快退（默认 15 秒）、上一轨、播放、下一轨、快进（默认 30 秒），字幕滚动，倍速、定时关闭 | 封面和控制在左，字幕占右半屏 |
| 设置 | 外观、播放、账号（改密码、退出所有设备）。管理员还能看到媒体库管理、扫描进度、网络代理、标签合并和缺失作品 | 同左 |

手机底部标签栏有 5 项：资料库、搜索、收藏、最近、设置。桌面没有标签栏，同样的入口放在左侧栏，“设置”在侧栏最下方。侧栏还有“我的评价”。手机的标签栏不加第六项，“我的评价”放在设置页账号一栏里。迷你播放条在手机上位于标签栏上方，在桌面上位于页面底部。

作品列表使用分页和图片懒加载。曲目树使用分批绘制，具体规则见“长列表”。是否引入虚拟滚动应由合成负载下的交互延迟与布局测量决定。

资料库的封面网格每页 40 部，用“上一页”和“下一页”两个按钮翻页，页码写在 URL 的 `?page=` 里，这样后退、刷新和分享链接都回到同一页。手机上固定两列。桌面上按最小 12rem 自动填充列，在常见的桌面宽度下一行 5 到 6 个。

封面卡片是指向作品详情的链接。封面图用 `/api/works/{id}/cover?size=thumb&v={cover_version}`，`<img>` 设 `loading="lazy"`。媒体 token 平时不放在地址里，而是放在 cookie 里（见[认证](auth.md)的“媒体请求的认证”），所以换了媒体 token 之后封面地址不变，浏览器缓存的封面一直可以用。每次显示都带着 cookie 回服务器确认，没变时只收到一个没有正文的 304，不再下载图片。浏览器禁用 cookie 时地址里照旧带 token。图片加载出来之前，以及 `has_cover` 为 `false` 时，显示一个纯色块。色相由作品 ID 算出，同一部作品每次都是同一个颜色，深色模式下调暗。`has_cover` 为 `false` 时色块中间再加一个音符图标，这时不请求封面。图片加载失败时先换一次媒体 token，再用地址里带新 token 的地址试一次，这样 cookie 不可用时也能加载，地址也变了，`<img>` 才会重新加载。还失败就留在色块上，不会反复重试。媒体会话的封面图由系统在页面之外读取，它的地址仍然带 token。作品详情和播放页的大封面不带 `size`，用原图。

### 作品详情

路由是 `/works/{id}`。“继续播放”按钮按下面的规则决定从哪里开始，规则写在 `web/src/lib/player/queue.ts` 的 `startPoint` 里：

- `progress.resumable` 为 `true`，并且那条轨道在列表里、没有缺失，就从这条轨道的 `position_ms` 继续。按钮写“继续播放”，下面一行写上次听到哪一轨的哪个时间。
- 其他情况从默认分组的第一轨开始，按钮写“播放”。默认分组是列表里第一条能播放的轨道所在的目录。导入的旧进度还没对上轨道时，按钮下面提示无法精确恢复。
- 这部作品正在播放时，按钮换成扬声器图标，写“正在播放”（暂停时写“已暂停”），点了打开全屏播放页。按钮下面一行写当前轨道和位置，不再写上次听到哪里。

管理员在“时长”下面多一行“位置”，每个位置占一行，写媒体库的名字和作品目录在这个媒体库里的路径，比如“本地作品 · 社团/RJ01234567”，用来在网盘或文件夹里找到这部作品。找不到了的位置排在后面，后面写“（已缺失）”。普通用户拿到的 `locations` 是 `null`，没有这一行，和侧栏的“媒体库”一样。目录名可能是一长串没有空格的字母，所以这一行可以在任意字符处折行，不会把信息栏撑宽。

页面的各组和设置页一样：小标题写在圆角列表的上面，每个操作占列表的一整行，说明和错误写在列表下面，相关的两组之间只隔 0.5rem。窗口宽度到 `lg`（1024 像素）时封面和信息左右并排，下面的“我的评价”对齐封面一栏、宽度和封面相同，“管理”对齐信息一栏，曲目占满两栏。`md` 起侧栏就占去 16rem，在 `md` 和 `lg` 之间并排的话信息栏只剩几个字宽，所以这段宽度和手机一样上下排列。

红心按钮和封面卡片上的红心是同一个开关，规则见下面的“收藏”。“标记为听过”调用 `finish` 并带上 `"manual": true`。这部作品正在播放时传当前轨道和分组。没在播放时，有进度就传进度里的轨道和它的目录，没有就传默认分组的最后一轨。作品已经听过并且没在重听时，这个按钮禁用。有进度时“我的评价”下面还有一行红字的“清除播放进度”，点了先在确认对话框里确认，再调用 `DELETE /api/me/progress/{id}`。确认用和强制重新抓取一样的对话框，不用浏览器自带的 `confirm()`。

曲目树由扁平的 `path` 按 `/` 拆出来，同一层里目录排在文件前面，目录和文件都保持第一次出现的顺序，也就是后端的自然排序。目录可以折叠，打开页面时只展开继续播放的那个分组和它的上级目录。音频和视频是可以点的按钮，点了就以它所在的目录为分组开始播放。缺失的文件显示为灰色加删除线，字幕、图片和其他文件只列出来，都不能点。

浏览器里，每个没缺失的文件和每个目录的右边有一个下载按钮，“曲目”标题的右边有“下载全部”。文件用 `GET /api/tracks/{id}/download` 下载原文件，目录用 `GET /api/works/{id}/download?group=<目录>` 打包成 zip，目录下面的子目录也在里面，“下载全部”不带 `group`，打包整部作品。下载交给浏览器自己的下载管理，链接没法带 `Authorization` 头，所以地址里带媒体 token。每次下载前都先换一个新的媒体 token：页面开着的时候存着的 token 可能已经过期，而浏览器的下载遇到 401 不会像播放器那样换 token 重试。换 token 失败时，“曲目”下面用红字写出原因，不开始下载。文件名由服务器的 `Content-Disposition` 决定。桌面版的外壳里没有这些按钮，因为 WebView 没有可以交出文件的下载管理，本机模式下文件本来就在这台电脑上。

管理员在详情页还能看到“管理”一栏，普通用户看不到。“编辑元数据”是一行，点了打开一个对话框，标题和底部的“取消”“保存”固定不动，中间的字段单独滚动，所以手机上保存按钮总在屏幕里。可以改标题、社团、声优、标签、发售日和 R18 标记，保存时整体调用 `PUT /api/works/{id}/metadata`。保存成功后页面重新取一次作品详情，而不是直接用接口的回答，因为这个回答可能比之后取到的播放进度更旧。声优和标签各写在一个输入框里，每行一个名字，去掉首尾空白、空行和重复项。名字里可能有逗号和顿号，所以只用换行分隔，打开再保存不会把一个名字拆成几个。标题不能为空，发售日为空时传 `null`，否则必须是真实存在的 `YYYY-MM-DD`。这些规则写在 `web/src/lib/metadata-form.ts`，不合法时不发请求，在对应的输入框下面提示。对话框里和保存之后都说明：保存后元数据标记为手动修改，普通的重新抓取不会覆盖它。保存成功的次数按作品记在 `web/src/lib/stores/metadata-saves.svelte.ts` 里，详情页看到这个数变了就重新读取，所以离开页面时发出的保存回来之后，再打开的页面也会更新，别的作品的页面不受影响。对话框关掉又重新打开过，旧的请求也不再关闭对话框，免得丢掉新写的内容。这部作品的保存还没回来、重新抓取还在进行，或者作品详情正在重新读取时，“编辑元数据”按钮禁用，离开详情页再回来也一样：正在保存的作品和正在抓取的任务按作品记在 `web/src/lib/stores/metadata-saves.svelte.ts` 里，回来时页面接着跟踪那个抓取任务，结束后解锁并重新读取。这样两次写入不会乱序到达服务器，重新打开的表单也总是从刚保存的数据开始。

“重新抓取”在它下面另一组的第一行，调用 `POST /api/works/{id}/refresh`。同一组第二行的“强制覆盖手动修改”勾上时带上 `force=true`，这一行的说明文字换成红字，说明会覆盖手动修改的元数据和导入或手动换过的封面，点“重新抓取”时还要在确认对话框里再确认一次。没有配置元数据来源时，接口返回 503 `upstream_error`，页面照原样显示服务器的说明。接口返回的任务用下文的任务流跟踪，变成 `done` 之后重新取作品详情。重新抓取完成后，页面上“已保存”的提示去掉。同一部作品已经在抓取时服务器返回那个任务，它可能是另一种模式，页面分不清保护还在不在，所以不管普通还是强制都去掉。这部作品的元数据还在保存时，“重新抓取”按钮禁用，免得较早的保存在抓取之后才到服务器，把抓取的结果又改回去。合同里的 `WorkDetail` 没有 `metadata_src` 和 `cover_src`，所以页面无法显示这部作品现在是不是手动修改过的，只能在说明文字里讲清楚规则。以后需要显示时，先按“怎么改这份合同”加字段。

### 收藏

封面卡片的社团名右边和作品详情页都有一个红心按钮，点了调用 `PUT` 或 `DELETE /api/me/favorites/{id}`。按钮先变状态再等服务器回答，失败时退回原来的状态，页面顶部提示“收藏失败”和原因，4 秒后自动消失。请求没回来之前按钮是禁用的，这样连点两次也只有一个请求，失败时退回的目标不会弄错。

同一部作品可能同时出现在资料库、搜索结果和详情页里，每个页面拿到的是各自的副本。所以切换后的状态放在 `lib/stores/favorites.svelte.ts` 里，按登录会话和作品 ID 记下，所有页面都从这里读，封面右上角的红心图标也跟着变。换了账号就是另一组记录，不会看到上一个账号的切换。页面拿到新的作品数据时，如果这次请求是在切换的请求结束之后才发出的，就以服务器的数据为准，丢掉这条记录，这样在别的设备上改过的收藏也会显示出来。请求还没结束，或者数据是在它结束之前请求的，就保留切换后的状态。

收藏页按加入时间倒序列出 `GET /api/me/favorites`，分页规则和资料库一样。在收藏页上取消收藏时，作品留在网格里直到下次加载，红心变成空心，再点一次就能恢复。缺失的作品也列出来，社团名前面标“已缺失”。

### 最近

最近页列出 `GET /api/me/history`，按最后播放时间倒序，封面上照常显示状态图标和进度条。每张卡片下面有“继续”按钮和进度，进度写成“当前位置 / 轨道时长”，听完的写“已听完”，没对上轨道的旧进度写“旧进度待匹配”。列表里的作品没有曲目，所以“继续”先取作品详情，再按作品详情一节的 `startPoint` 规则开始播放。详情回来时如果已经换了账号，或者已经离开了最近页，就不再开始播放。这部作品正在播放时按钮写“正在播放”，点了打开全屏播放页。

### 评分和短评

规则见[接口合同](contract.md)的“评分和短评”。评分和短评只有自己看得到，和 DLsite 的平均分无关，平均分照旧显示在详情页的“评分”一行。

封面卡片在 `my_rating` 不为空时，在封面左下角显示一个深色的小胶囊，里面是五颗星，评到的几颗用强调色，其余用灰色。胶囊在浅色和深色模式下都是深色的，这样在任何封面上都看得清，所以里面的强调色用深色模式的 `#5aa5f7`。没有评分（包括只写了短评）时不显示。

作品详情在曲目上面有一组“我的评价”，样子和设置页的分组列表一样。第一行是“评分”和五颗星，每颗星是一个 44 像素见方的按钮，名字是“评 N 星”，当前评分那一颗的 `aria-pressed` 为真。点一颗星马上保存，用 `PUT /api/me/reviews/{id}` 发出新的评分和原来的短评。再点当前评分那一颗是清除评分，这时如果也没有短评，就改发 `DELETE`，因为服务器不接受两样都为空的 `PUT`。第二行显示短评全文的前几行，没有短评时写“写短评”，点了打开编辑表单。

编辑表单在手机上从底部升起，宽窗口里居中，和添加媒体库的表单一样，左上角“取消”，右上角“保存”。里面有同样的五颗星（这里点星只改表单，不马上保存）、短评输入框和“n / 2000”的计数。计数按服务器的规则算：先去掉首尾空白，再数 Unicode 码位，所以一个 emoji 算一个字。去掉的空白按 Rust 的 `str::trim`，也就是 Unicode 的 White_Space，和 JavaScript 的 `trim` 在 U+0085 和 U+FEFF 上不同。超过 2000 时计数变红，说明上限，“保存”禁用。保存时发出去掉首尾空白的短评，空的短评发 `null`，评分和短评都空时发 `DELETE`。已经有评价时，表单最下面有“删除评价”，点了先在表单里问一次，确认之后发 `DELETE`。保存或删除失败时表单不关，在里面显示原因，写好的内容还在。这些规则写在 `web/src/lib/review-form.ts`，Vitest 覆盖。

和收藏一样，同一部作品在各个页面里是各自的副本，所以写入的结果放在 `web/src/lib/stores/reviews.svelte.ts` 里，按登录会话和作品 ID 记下，详情页和所有封面卡片都从这里读。点星之后马上显示新的评分，服务器回答之后换成回答里的 `Review`，失败时退回原来的评价，在这一组下面提示“评分没有保存”和原因。请求没回来之前星星和“保存”都禁用，因为每次 `PUT` 都整体替换评价，两个请求乱序到达会留下旧的那个。页面拿到新的作品数据时，按收藏那一节的规则决定以服务器的数据为准还是保留写入的结果。

“我的评价”页 `/reviews` 列出 `GET /api/me/reviews`，网格和翻页和收藏页一样，最近改过的在前。列表里没有短评，要看全文进详情页。缺失的作品也列出来。没有评过任何作品时，页面说明在详情页的“我的评价”里点星星或者写短评。

### 搜索和排序

搜索页的全部状态都在 URL 的查询参数里：`q`、`tag`、`circle`、`va`、`root`、`sort`、`order`、`seed` 和 `page`，含义和[接口合同](contract.md)里 `GET /api/works` 的参数相同。页面只读 URL，控件只改 URL，所以刷新、后退和分享链接都回到同一个结果。解析和生成写在 `web/src/lib/search-state.ts`，不认识的值按默认值处理，默认值不写进 URL，同样的状态总是生成同样的链接。

- 搜索框输入停顿 300 毫秒后才更新 URL。输入法正在组词时不更新，组词开始时还没发出的那次更新也取消，组完再算。停顿还没到 300 毫秒就点了别的链接或者后退时，这次输入作废，不会再把页面带回搜索页。从空搜索开始输入时新增一条历史记录，之后继续修改关键词只替换这一条，这样后退会离开这次搜索，而不是一个字一个字地退回去。
- 筛选和排序每改一次就新增一条历史记录，并回到第 1 页。翻页用普通链接，也会新增历史记录。
- 标签、社团和声优的筛选各是一个选择面板（`ListPicker`）：点按钮弹出，手机上从底部升起，桌面上居中。顶部是搜索框和“按作品数”“按名称”两种顺序，默认作品多的在前，下面是带作品数的列表，第一行“全部”清除这个筛选。搜索在前端做，名字先做 NFKC 归一化、统一大小写并去掉空格再比子串，所以全角、半角和大小写不同的写法都能搜到。上下方向键移动，回车选中，搜索时回车直接选第一条。面板关着时不渲染列表，一页上几个选择器各有几百行也不拖慢页面。媒体库只有几个，仍然用原生 `select`。
- 标签、社团和声优的下拉列表来自 `/api/tags`、`/api/circles` 和 `/api/vas`，后面带作品数。媒体库的下拉列表来自 `/api/admin/roots`，只有管理员能看到。链接里的 ID 不在列表里时，下拉框里显示“已不存在”，结果照常请求，后端会返回空列表。
- 排序可选入库时间、发售日、评分和随机，前三种可以切换升序降序。选随机时生成一个 0 到 2^31 之间的 `seed` 写进 URL，翻页时带着同一个 `seed`，所以页与页之间不重复也不遗漏。“换一批”换一个新的 `seed`。URL 里是随机排序却没有 `seed` 时，页面先用替换的方式补上一个再请求。
- 没有关键词也没有筛选条件时不请求作品列表。手机上这时显示最近搜索，最多 8 条，按回车或者搜索框失去焦点时记下来，马上出现在列表里，同时存进 `localStorage`。存储不可用时，这个列表只保留到页面重新加载。

桌面上搜索框只有侧栏顶部的那一个，搜索页自己的搜索框只在手机上显示。在别的页面用侧栏搜索框输入，会跳到搜索页。资料库页也有同样的排序控件，参数同样写在 URL 里，但资料库没有关键词和筛选。

侧栏的“媒体库”一栏列出 `/api/admin/roots` 里的媒体库，旁边的圆点表示状态，点了打开按这个媒体库筛选的搜索页。普通用户读不到这个接口，所以看不到这一栏。

### 媒体库连不上

任何接口返回 503 `storage_unavailable` 时，页面在原来放内容的位置显示“媒体库暂时无法访问”，说明作品、收藏和播放进度都还在，并给一个“重试”按钮。这个错误不清除登录状态，也不把作品当成已删除。错误响应里没有媒体库字段，所以提示里的名字按顺序这样找。页面正在按某个媒体库筛选时，用它的名字。否则当前用户是管理员时，用 `/api/admin/roots` 里状态为 `unavailable` 的媒体库。都没有时，用服务器的 `message`，按 [API 设计](api.md)的约定，它会写出媒体库的名字。规则写在 `web/src/lib/storage-error.ts`。

播放时 `prepare` 返回这个错误，迷你播放条和全屏播放页显示服务器给的原因，后面加“恢复之后点重试”。连不上服务器本身（网络断了，或者反向代理后面的服务器停着）不在此列，播放器会自己重试，规则见[媒体处理与播放](media.md)的“播放流程”第 5 步。

设置页对管理员列出每个媒体库的名字、类型、作品数、上次扫描时间和状态（正常、无法访问、还没检查），有“刷新”按钮。有媒体库无法访问时，下面再说明里面的作品和用户数据都还保留着。刷新失败时，列表上方提示失败原因，说明下面是上次取到的状态，可能已经过时。

### 管理员的设置页

设置页对管理员显示媒体库、扫描进度、网络代理、合并标签、任务、缺失的作品和位置，最后是账号。“外观”排在最前面，手机上也不用先翻过管理员的几组才找到主题。手机上和较窄的窗口里这些排成一列。窗口宽到 1280 像素以上时分成两列，左列是媒体库、扫描进度、网络代理和合并标签，右列从“外观”开始，后面是任务、缺失列表和账号，免得右半屏空着。普通用户读不到管理接口，页面仍显示外观、播放和账号设置。账号一栏有“修改密码”“退出登录”和“退出所有设备”。“修改密码”在这一栏里展开一张表单，填当前密码、新密码和确认新密码。没填当前密码、新密码不到 8 个字符（按码点数，和服务器数 Rust 的 `char` 一样）或者两次输入不一样时，提交之前就在对应的字段下面提示，规则在 `web/src/lib/password-form.ts`。提交后调 `PUT /api/auth/password`，成功后这台设备的 token 也失效了，所以清掉登录状态回到登录页，登录页提示“密码已经改好，请用新密码登录”。当前密码不对时服务器同样回答 401，但错误码是 `invalid_credentials`，而客户端只把别的 401 当成登录过期，所以这时仍然登录着，表单清空当前密码一栏并说明原因。表单里另有一个隐藏的用户名字段，让密码管理器知道新密码属于哪个账号。“退出所有设备”先在这一栏里确认，再调 `POST /api/auth/logout-all`，成功后这台设备也回到登录页，因为它的 token 同样失效了。失败时留在设置页并显示原因。桌面版本机模式这三项都没有，那里的登录由外壳管理。媒体库的每一行把类型、作品数和状态放在名字下面一行，上次扫描时间单独占一行，右边只留一个信息按钮和“扫描”按钮，手机上不会挤成好几行。写在 `config.toml` 里的媒体库在名字旁边有“由配置文件管理”的标记。

- **扫描**：媒体库列表的每一行有“扫描”按钮，下面有“扫描全部”和完整扫描勾选框。当前界面仍写着“完整扫描（刷新网盘缓存）”，这个标签不准确，实际行为以本段为准。勾上之后请求体带 `"full": true`，不勾时不带这个字段。完整扫描对 OpenList 和 WebDAV 都会关闭目录摘要跳过，会多花时间和请求，但不会强制刷新 OpenList 缓存。“扫描全部”返回的任务 ID 顺序合同没有规定，所以这些任务只叫“全部媒体库 1/2”这样的名字，不对应到具体的媒体库。
- **媒体库正在扫描**：某个媒体库有排队或进行中的扫描时，它那一行用扫描状态代替上次扫描时间，比如“排队等待扫描”或“正在扫描 · 同步轨道 25/100”，扫描结束、媒体库列表重新读取之后再换回上次扫描时间。任务快照里没有媒体库，所以只能按页面发出的请求对应：单个媒体库的扫描只对应那一个，“扫描全部”对应每一个，但分不清哪个任务是哪个媒体库，所以只写“正在扫描”不写阶段，其中几个任务结束、只剩一个在运行时也一样。打开页面之前就在运行、不是从这里发出的扫描，只有在只有一个媒体库时才能对应上。规则在 `web/src/lib/tasks/root-scan.ts`。
- **添加媒体库**：列表下面的“添加媒体库”打开一张表单。手机上它从底部升起，宽窗口里居中显示，和 iOS 的表单页一样，左上角“取消”，右上角“添加”或“保存”。最上面是“本地文件夹”“OpenList”和“WebDAV”三段的分段控件。本地文件夹填路径，要求是绝对路径（Unix 路径、Windows 盘符路径或 UNC 路径），文件夹是否存在由服务器检查。OpenList 填地址、目录、用户名和密码，“高级”里还有同时列目录的请求数和每秒取直链的次数，留空用服务器的默认值 4 和 1。WebDAV 填同样的四项，地址是服务的根地址（比如 `https://nas.example.lan/dav`），目录是媒体库在这个服务下的路径，“高级”里只有同时列目录的请求数，因为 WebDAV 没有取直链这一步，请求里也不带 `link_rate`。ID 也在“高级”里，默认由名称生成：NFKD 分解之后去掉附加符号，只留 ASCII 字母和数字并转成小写，其他字符换成一个 `-`，最多 32 个字符。名称里没有 ASCII（比如“示例作品”）时用 `library`，和已有的 ID 重复时在后面加 `-2`、`-3`，因为配置和数据库里的媒体库共用一个命名空间。手动改过 ID 之后名称不再改它，把 ID 清空则重新跟着名称走。表单上写明 ID 添加之后不能修改。保存的请求发出去之后，回答到来之前表单的字段都锁住，所以“仍然保存”重发的总是表单上显示的内容。名称和地址去掉首尾空格，路径、目录和用户名按原样发送，因为目录名可以以空格结尾，去掉之后指的就是另一个目录。规则在 `web/src/lib/roots/form.ts`，字段的错误显示在各自下面，和服务器的 400 用同样的规则，所以多数错误不用等服务器回答。
- **自动扫描和监视**：“高级”里还有“自动扫描间隔”和“监视文件夹变化”，规则见[接口合同](contract.md)的“自动扫描和目录监听”。间隔是一个下拉框，“关闭”之外只列不短于最短间隔的选项（本地从 5 分钟起，OpenList 和 WebDAV 从 30 分钟起，最长 30 天），说明文字写出当前类型的最短间隔。配置文件里写的不在选项里的间隔（比如 2 小时 30 分钟）也作为一项列出，打开再保存不会改掉它。从本地换成 OpenList 或 WebDAV 时，太短的间隔在提交前就报错。“监视文件夹变化”只对本地媒体库显示，新建时在桌面版的本机页面里默认勾上，其他地方默认不勾，和服务器的默认值一致。`PUT` 整体替换设置，所以这两个值每次都按表单上的发出去，不留给服务器取默认值。保存的设置是开启监视、服务器却报告 `watching` 为 `false` 时，表单说明现在没有在监视。媒体库列表的每一行在上次扫描时间下面再加一行，正在监视时显示绿点和“正在监视”，开了自动扫描时显示“下次自动扫描”的时间，两样都没有时不占这一行。配置文件里的媒体库在只读的详情里列出这两项。
- **连接检查**：保存时服务器检查本地路径、登录 OpenList 并列一次目录，或者对 WebDAV 的目录发一次 `Depth: 0` 的 `PROPFIND`。OpenList 或 WebDAV 的检查失败（502 `upstream_error` 或 503 `storage_unavailable`）时，表单显示服务器给的原因，下面有“仍然保存”，它带上 `"skip_check": true` 重发同一个请求。在那之后改了任何字段，“仍然保存”就消失，因为它要发的已经不是表单上的内容。
- **桌面版选文件夹**：在桌面版的本机页面里，路径下面有“选择文件夹…”，调用外壳的 `pick_folder` 打开系统对话框，见[桌面版](desktop.md)的“外壳给页面的命令”。页面没有引入 `@tauri-apps/api`，直接调 Tauri 注入的 `window.__TAURI_INTERNALS__.invoke`，这和那个包内部的调用相同。按钮只在 `window.isTauri` 为真、页面不是打包的选择页、并且 `desktop_state` 调用成功时出现，因为远程页面调不了这个命令，而本机页面和远程页面只能这样区分。浏览器和远程页面里没有这个按钮。早于这个命令的外壳也能通过 `desktop_state` 的检查，所以第一次点按钮时 Tauri 回答命令不存在或没有权限，页面就说明这个版本还不能选文件夹、请直接填写路径，并在这次打开页面期间不再显示按钮。规则在 `web/src/lib/desktop/folder-picker.ts`。
- **修改媒体库**：每一行的信息按钮打开同一张表单。配置文件里的媒体库只显示设置，没有输入框和删除按钮，并说明要改 `config.toml` 里对应的 `[[roots]]` 再重启服务。数据库里的媒体库可以改名称、类型和设置，ID 只显示不能改。密码框总是空的，已经保存了密码时旁边写“已设置密码”，留空表示沿用，请求里的 `password` 是 `null`。地址的协议、主机或端口变了时必须重新填写密码，表单在提交之前就拦下并说明原因，和服务器的 400 一致，免得保存的密码被发到别的服务器。从本地改成 OpenList 或 WebDAV、在 OpenList 和 WebDAV 之间互换（即使地址没变），或者原来没有保存密码时也必须填写，因为服务器只为同一种服务、同一个来源沿用保存的密码。
- **密码**：密码不进日志，不显示在页面上。提交时密码只留在发出的请求里，表单里的密码马上清空。连接检查失败时那份请求留在组件的普通变量里给“仍然保存”用，不放进响应式状态，改了字段或关掉表单就丢掉。其他错误之后表单提示密码已经清空、要重新填写。
- **删除媒体库**：表单最下面的“删除媒体库”先弹出红色的确认框，说明这个媒体库里的作品会标记为缺失，收藏和播放进度保留，之后可以在“缺失的作品和位置”里清理，用同样的 ID 重新添加并扫描会恢复。删除成功后媒体库列表和缺失列表都重新读取。添加、修改和删除之后读媒体库列表时，已经在路上的那次请求的回答直接丢掉，因为它可能是改动之前取到的（`roots.reload()`）。这个媒体库正在扫描或排队扫描时服务器返回 409 `scan_running`，表单说明原因，可以去“扫描进度”里取消扫描，或者点“扫描结束后删除”。任务快照里没有媒体库，页面不知道哪个扫描属于它，所以点了之后每 3 秒重试一次删除，直到成功或者遇到别的错误，“不等了”或者关掉表单就停止重试。规则在 `web/src/lib/roots/retry.ts`。
- **错误文字**：每个错误码都有中文说明，写在 `web/src/lib/roots/errors.ts`。`root_exists` 写出重复的 ID 并让用户去“高级”里换一个，`root_read_only` 说明要改配置文件，`scan_running` 分保存和删除两种说法，`invalid_request` 和检查失败带上服务器的原因，`not_found` 说明媒体库已经不在并刷新列表，网络错误让用户检查网络后重试。
- **扫描进度**：每个扫描任务一张卡片，显示状态、四个阶段（发现作品、同步轨道、抓取元数据、读取封面）里的当前阶段和计数、进度条，以及连接状态。阶段从任务的 `message` 里读出来，规则在 `web/src/lib/tasks/labels.ts`，认不出的说明照原样显示。打开设置页时，已经在排队或运行的扫描也会出现在这里，所以离开再回来还能看到进度。
- **排队顺序**：扫描一次只跑一个，卡片按服务器运行它们的顺序排列：正在运行的在最上面，然后是排队中的，按 `queue_position` 从小到大，最后是已经结束的，列表下面的提示也这样说明。排队中的卡片在状态里写出排第几，比如“排队中 · 第 2 位”。不是下一个开始的排队卡片上有“移到最前”，它调用 `POST /api/tasks/{id}/move-to-front`，新的位置由各张卡片的任务流送来，不在页面上先改。正在运行的扫描没有这个按钮，要先扫描别的媒体库，只能取消它。规则在 `web/src/lib/tasks/queue-order.ts`。
- **取消和离开**：卡片上的“取消任务”调用 `POST /api/tasks/{id}/cancel`，之后继续读任务流，等服务器发来 `cancelled` 的快照。离开设置页只关闭任务流，不取消任务，页面上也这样提示。卡片在任务结束后留着，点“移除”才去掉。
- **后台探测**：扫描完成和探测完成是两件事。扫描卡片在 `done` 时写明后台探测另外计算，卡片下面单独一行显示排队和进行中的 `probe` 任务数。任务列表只能去掉一种任务，不能只看某一种，所以这个数字来自 `state=queued` 和 `state=running` 两页各 100 条里种类为 `probe` 的条数，页满时数字后面加“+”。扫描发现使用独立的查询，对这两种状态都带上 `exclude_kind=probe`，逐页读完后筛出扫描任务，不设页数上限。这样大量探测不会占用扫描发现的分页，其他种类的任务也不会把较早的排队扫描挡在截断范围之外，重新打开设置页仍能看到它们。有扫描或探测在进行时每 3 秒刷新一次，否则每 15 秒一次，写在 `web/src/lib/stores/task-activity.svelte.ts`。
- **任务**：`GET /api/tasks` 每页 20 条，可以按状态筛选，六种状态都有中文名，`interrupted` 是“已中断”。每首音频第一次播放都会排一次响度分析，它们会把扫描和转码挤到后面的页里，所以列表默认带上 `exclude_kind=analysis`，勾上“显示响度分析”才列出来，取消勾选又藏起来，两种情况都回到第一页。藏起来的分析仍然在任务表里，结束时服务日志也各有一行。没结束的任务有“取消”按钮。按状态筛选时，任务结束可能让当前页变空，这时跳回最后一页还有任务的那一页。
- **缺失的作品和位置**：两组带勾选框的列表，有“全选”。“清理所选”先弹出确认对话框，说明删除作品会一起删掉收藏和所有人的播放进度、删除位置会让指向它的播放进度不再对应轨道，并且不能撤销。确认后才调用清理接口。服务器一次最多收 1000 个 ID，选得更多时页面提示分批清理，不发请求。清理的结果写出删了几部作品和几个位置，期间重新出现、没被删除的条目也写出来。返回 409 `scan_running` 时提示有扫描正在进行，勾选保持不变，旁边有“重试”按钮，扫描结束后点它把确认过的那次请求原样再发一次。之后改了勾选，“重试”就消失，要重新走确认对话框，免得没确认过的作品被删掉。扫描结束后列表自动重新读取。
- **网络代理**：一个“元数据代理”输入框，下面说明它管哪些请求、留空时怎样，桌面版本机模式多一句“不会自动使用系统代理”。“测试连接”用框里现在的值调 `POST /api/admin/settings/proxy-check`，不保存。DLsite 回答 2xx 或 3xx 时显示状态码和用时，别的状态码说明连上了但被拒绝，没有回答时直接显示服务器给的原因，它已经以“连不上 DLsite”开头。“保存”在值没变时禁用，保存后框里换成服务器整理过的写法。按回车也是保存。文字规则在 `web/src/lib/metadata-proxy.ts`。
- **合并标签**：两个字段分别选被合并的标签和目标标签，用的是和搜索页筛选一样的选择面板，选项来自 `GET /api/tags`，带作品数。“合并进”的列表不含已经选作被合并的那个标签。选好被合并的标签后，“合并进”的面板在全部标签之前先列出“名字相近”的标签：归一化以后相同、只差一个字（比如繁简不同的 耳语 和 耳語）、较长的名字差两个字，或者一个包含另一个，近的在前，同样近的作品多的在前，最多 8 个。重复的标签多半是这样的另一种写法，不用翻完整个列表。两个相同或有一个已经不在列表里时按钮禁用并说明原因。确认对话框写明被合并的标签会删除，作品和别名转到目标标签。成功或失败之后，以及扫描结束之后，都重新读取标签列表，因为扫描可能带来新的标签。

### 任务进度流

`GET /api/tasks/{id}/events` 要带 `Authorization` 头，所以用 `fetch` 读，不用 `EventSource`。`web/src/lib/api/sse.ts` 把收到的文本切成事件，`web/src/lib/tasks/task-watch.ts` 的 `watchTask` 负责跟踪一个任务：

- 连上之后第一条事件就是当前快照，之后每条 `snapshot` 事件都交给页面，收到结束状态的快照就停止。
- 连接在任务结束前断开时重新连接。连接收到过事件，就等 1 秒再连，否则按 1、2、4、8、15 秒依次加长。连续 3 次连接都没收到任何事件，就改成每 2 秒查一次 `GET /api/tasks/{id}`，出错时间隔加倍，最长 30 秒。
- 响应不是 `text/event-stream`（比如中间的代理改写了它）时，直接改成轮询，不再重试。连上之后 45 秒内一个字节都没收到（服务器每 15 秒发一次 `: ping`）时，当作连接被代理挡住，断开重连。
- 4xx 错误（比如 404 `not_found`）说明再试也没用，停止跟踪并显示原因。401 和其他请求一样清除登录状态。
- `close()` 只断开连接、停止计时器，不发任何请求。取消任务是单独的接口调用，由页面在用户点“取消任务”时发出。
- 一个页面最多同时开 3 个任务流，再多的任务从一开始就轮询。浏览器对同一个源只开 6 个 HTTP/1.1 连接，任务流全占满之后，取消和其他请求都要排队等它们结束。

### 播放器

迷你播放条只在 `(app)` 布局里出现，手机上在标签栏上方，桌面上在侧栏和内容区下面占满一行。点封面和标题打开全屏播放页 `/player`。全屏播放页单独放在 `(fullscreen)` 路由组里，没有侧栏和标签栏，左上角的按钮返回上一页。页面下半部分（桌面上是右半屏）有“字幕”和“播放队列”两个标签。桌面上整页正好占满窗口，不出现页面滚动条：封面和下面的控制一起放在左半屏的竖直中间，窗口够高时封面按 4:3 显示完整大小，不够时才缩小，字幕和播放队列在右半屏里自己滚动。Playwright 还检查封面和标题之间不超过 48 像素，倍速和定时关闭离窗口底边至少 32 像素。“字幕”和“播放队列”两个标签的选中项用 `--segment` 颜色，深色模式下比标签栏的底色浅，和 iOS 的分段控件一样。1280×720 和 1440×900 两个窗口尺寸由 Playwright 检查。字幕列表跟着播放位置滚动，当前一行高亮，点一行跳到那个位置。播放位置只跟着媒体元素自己的 `timeupdate` 事件更新，大约每秒 4 次。Vidstack 的 `time-update` 每一帧都触发，用它时进度条每秒重画 60 次，同样条件下播放页的主线程时间是现在的三倍。等待转码时封面上盖一层，显示进度和“可以切到别的轨道”，出错时显示原因和“重试”。

桌面上迷你播放条的标题右边是一条进度滑块，左边写已经播到的时间，右边写总时长，拖动或者点一下就能跳转。它和全屏播放页的进度滑块是同一个组件（`web/src/lib/components/Scrubber.svelte`），拖动时时间跟着滑块走，松开才跳转。拖动期间切换轨道时取消这次拖动，滑块恢复显示新轨道的进度，继续移动或松开都不会把旧位置应用到新轨道，等待准备时也一样。两边的时间都按总时长的字数留出宽度，所以已播放的时间多出一位时滑块不会跟着移动。手机上的迷你播放条放不下滑块，只在顶边有一条细进度线，要拖动就打开全屏播放页。

后退和前进的秒数在设置页“播放”一栏里选，默认 15 秒和 30 秒，可选 5、10、15、20、30、45、60、90 秒，存在 `UserSettings` 里跟着账号走。全屏播放页、视频的全屏控制栏，以及桌面上迷你播放条播放键两边的两个按钮都用它们，按钮图标里的数字跟着变。手机上的迷你播放条只放得下播放和下一轨，没有这两个按钮。设置还没读到、或者服务器的回答里没有这两项（更早的服务器）时，按默认的秒数。播放器从 `PlaybackExtras.svelte` 拿到秒数并检查范围，设置页显示和保存的也是检查过的值，所以从旧服务器读到的设置在保存时会补上这两项。规则在 `web/src/lib/player/skip.ts`。

音量控制在全屏播放页的播放按钮下面，是一个静音按钮加一条灰色的滑块，样子和 iOS 的播放器一样。桌面上迷你播放条右端也有一份，手机上的迷你播放条没有，因为手机用机身按键调音量，播放条也放不下。视频全屏时的控制栏里同样有静音按钮和滑块，全屏宽度不到 560 像素（竖着拿的手机）时放不下，就不显示。iOS Safari 不允许网页改音量，给媒体元素的 `volume` 赋值没有效果，读回来总是 1，所以播放器启动时新建一个 `audio` 元素，把音量设成 0.5 再读回来，读到的不是 0.5 就不显示滑块，只留静音按钮，也不看 User-Agent，因为桌面模式的 iPad 会报成 macOS。焦点在全屏播放页或迷你播放条里时，上下方向键每次调 5%。焦点在进度条、音量滑块、输入框，或者字幕和播放队列面板里时方向键照旧归它们，不调音量。静音时调高音量会取消静音，调低则不变，免得丢掉取消静音后要回到的音量。音量调到 0 再点静音按钮，回到 50%。

音量和静音状态存在 `localStorage` 的 `kikoeru-neo.volume` 里，读写都包在 `try` 里，存储不可用或内容不对时从 100%、不静音开始。规则在 `web/src/lib/player/volume.ts`。每次设置来源之后，包括 HLS 和转码回退之后重新加载的来源，播放器都把音量再交给媒体元素一次。Vidstack 在 `can-play` 时会把自己的属性（100%、不静音）写回媒体元素，换视频和音频时还会换一个新元素，所以 `VidstackHost.svelte` 和倍速一样在 `volumechange`、`loadedmetadata`、`playing` 事件上把元素改回播放器的音量。只有 iPhone 的原生视频全屏例外，那里显示的是系统的控制栏，用户在上面改的静音会记到播放器里，不再改回去。新来源开始播放之前的变化仍然当作 Vidstack 的重置，所以全屏中途换 token 重新加载时也不会丢掉静音。

### 音量均衡和波形

设置页的“播放”一栏有“音量均衡”开关和“目标响度”滑块，存在 `GET/PUT /api/me/settings` 里，跟着账号走，默认关闭、-16 LUFS。改动立刻生效，在后台保存。每次 `PUT` 都替换整个对象，所以同一时间只发一个，发完再发最新的值。也因为这样，这个账号的设置读到之前，音量均衡的开关和强调色的色块都不能用，免得用默认值盖掉已经保存的设置。保存失败时退回服务器上一次确认的值并显示原因。换了账号时，旧账号还没发完的请求照样发完，但它的回答不再显示，新账号的改动在它之后发出，不会丢。规则在 `web/src/lib/stores/user-settings.svelte.ts`。

打开均衡后，播放器把音频元素接进 Web Audio，经过一个 GainNode 再输出。增益是“目标响度减去积分响度”的分贝数，但不让真峰值超过 -1 dBTP，所以安静的轨道最多只提到不削波为止。没有测过响度的轨道按原音量播放，响度到了再用 50 毫秒渐变过去，换轨道时也一样，免得出现爆音。元素自己的音量和静音照旧，浏览器先按它们处理，再交给 GainNode，所以音量滑块和锁屏控制都不受影响。规则在 `web/src/lib/player/loudness.ts` 和 `normalizer.ts`。

- 接进 Web Audio 的元素只能通过 AudioContext 发声，而 AudioContext 只能在用户手势里开始运行。所以播放器在 `pointerdown`、`pointerup`、`keydown` 和打开开关的那次点击里创建它，之后一直保留。关掉均衡只把增益设回 1，不把元素断开，因为一个元素一旦接入就不能再接回原来的输出。
- AudioContext 还没运行时不接元素，等它运行起来再接，否则会没有声音。Vidstack 换来源时会换一个新的 `audio` 元素，新元素加载后接入，已经离开页面的旧元素断开。
- 只处理音频。视频的元素从不接入，HLS 和原生视频播放器保持原样，设置页的说明也写了“视频不调整”。服务器对视频的响度和波形回答 404 `not_applicable`，所以前端也从不为视频请求这两个接口。
- iOS Safari 切到后台或锁屏后会停掉经过 Web Audio 的声音。它也是不能改音量的那个浏览器，所以和音量滑块用同一个检测：检测不通过时开关显示为不可用，并说明原因，播放器也不请求响度。
- 作品详情里已经带了 `TrackItem.loudness`。是 `null` 的轨道在开始播放时请求 `GET /api/tracks/{id}/loudness`，回答 202 时轮询任务，`done` 后再请求一次。任务失败、请求出错，或者连续三轮都是 202，就放弃，按原音量播放。换轨道时停止上一条轨道的轮询。响度和波形都等 `prepare` 有了结果（直接播放或者开始转码）才请求：在那之前服务器还不知道远端文件会不会由转码任务下载，提前请求会让它多下载一次。前端测到的响度只在同一次详情加载得到的轨道对象内复用，同时检查测量时的文件大小。重新加载详情后，若服务器返回 `loudness: null`，即使轨道 ID 和大小没变也重新请求，因为文件可能只变了修改时间。

桌面版（宽度不小于 768 像素）在迷你播放条和全屏播放页的进度滑块后面画波形，手机上不请求。`GET /api/tracks/{id}/waveform` 给 1000 个字节，前端按每 3 个像素一根柱子把它们折叠成柱子，每根取覆盖范围里的最大值，免得短促的响声被平均掉。柱子画成一条 SVG 路径，只随宽度变化。已播放的部分是同一条路径的另一份副本，按进度改它的 `clip-path`，所以播放时只重绘这一层，不重新布局。有波形时滑块的轨道变成透明，拖动和方向键照旧由滑块处理。浏览器的 HTTP 缓存按 `ETag` 保存波形一周。长度不是 1000 字节的回答（比如代理的错误页）当作没有波形，仍然显示普通的进度条。规则在 `web/src/lib/player/waveform.ts`、`analysis.svelte.ts`、`web/src/lib/components/Waveform.svelte` 和 `Scrubber.svelte`。

### 主题

设置页“外观”一栏的第一行是“主题”，一个分段控件，三项是“跟随系统”“浅色”“深色”，默认“跟随系统”。选择记在这台设备的 `localStorage`（`kikoeru-neo.theme`）里，不进账号设置，也不改接口合同，因为同一个人常常想让手机跟随系统、电脑一直用深色。

根元素的 `data-theme` 是 `light` 或 `dark`，`app.css` 的深色变量只认这个属性，不再读 `prefers-color-scheme`。`app.html` 在 `<head>` 里同步加载 `static/theme.js`，它在页面画出任何东西之前按存下的选择和系统的设置写好 `data-theme`，把 `theme-color` 改成当前主题的背景色，`color-scheme` 改成当前主题（样式表加载之前，浏览器按它画页面底色），所以选了深色的页面在浅色系统上打开也不会先闪一下白。这个脚本是同源的外部文件，CSP 的 `script-src 'self'` 允许它，不需要给内联脚本加哈希。应用启动后，`web/src/lib/stores/theme.svelte.ts` 接管：选“跟随系统”时随系统切换，设置里换了选择或者别的标签页换了选择，都立刻生效。`static/theme.js` 不能导入 `web/src/lib/theme.ts`，两边各写了一遍同样的规则，`theme.test.ts` 把脚本在假的 `document` 里跑一遍，和模块的结果逐一比较。

### 强调色

设置页的“外观”一栏还有八个色块，对应 `UserSettings.accent` 的八个名字，选中后立刻生效，保存方式和音量均衡一样。强调色用在按钮、链接、开关和进度条上，`--accent` 是填充色，上面的文字是白色，`--accent-text` 是放在页面背景上的文字和图标颜色。每个颜色从 iOS 的同名系统色出发，浅色主题下调暗到白字在填充色上、填充色作为文字在 `--bg` 上都达到 4.5:1。深色主题的填充色不变，文字色调亮到在 `--surface-raised` 上达到 4.5:1。蓝色保持原来的色值。

### 长列表

作品、搜索结果、收藏、最近和任务列表使用分页。标签、社团和声优使用可搜索的选择面板，播放队列只列当前分组。需要控制一次渲染数量的是作品详情中可以展开的大目录。

曲目名可以折行，行高不固定。`Progressive.svelte` 先绘制 60 行，之后每帧增加 120 行，避免展开大目录时一次创建全部节点。用假数据模式生成数百或数千个文件，测量首批出现时间和最终补齐时间，并确认全部绘制后页内搜索仍能找到每一行。

### 视频

视频和音频共用根布局里的同一个 Vidstack 元素，所以切换页面时视频的声音照样继续。播放视频时，全屏播放页换成以画面为主的布局，页面里留一个按探测出的宽高比（没有时按 16:9）画出的黑框，`VidstackHost.svelte` 把媒体元素用固定定位盖在这个框上，并跟着它的大小和页面滚动移动。正在准备或者等待转码时，媒体元素回到不可见的状态，框里显示和封面上一样的等待或出错提示。哪种情况怎么显示由 `web/src/lib/player/video.svelte.ts` 里的纯函数 `presentation` 决定。

- **视频的播放页**：桌面上画面占满内容区的宽度，在控制条上方能放下的范围内按宽高比尽量放大，所以 1280×720 的窗口里画面也超过窗口宽度的六成。标题、作品名、画中画和全屏按钮移到顶栏，进度条下面一行左边是音量，中间是播放按钮，右边是倍速和定时关闭，整页不出现滚动条。ass 和 WebVTT 字幕都画在画面上，所以视频没有“字幕”标签页，“播放队列”放在顶栏右端按钮打开的侧栏里，默认收起，打开后画面跟着变窄。手机上画面在顶部，左右贴边、不带圆角，下面依次是标题、进度条、控制和播放队列。音频轨道的播放页不变。
- **视频小窗**：播放视频时离开播放页，同一个媒体元素改成固定在页面一角的小窗，接着播放，不重新加载来源，也不另建媒体元素。小窗在桌面上宽 400 像素，在手机上占屏幕宽度的六成，高度按视频的宽高比，放在标签栏和迷你播放条上面。桌面上左边的两个角让开 16rem 的侧栏，免得挡住导航。小窗可以拖动，松手时吸附到最近的角，这个角存在 `localStorage` 的 `kikoeru-neo.video-corner` 里，读写都包在 `try` 里。点画面暂停或继续，拖动不算点。右上角三个按钮：“放大”回到播放页，“画中画”交给浏览器的画中画（不支持时不显示，画中画期间小窗隐藏），“关闭”收起小窗而声音继续，这时迷你播放条的封面位置换成正在播放的画面，媒体元素用和播放页一样的跟随方式盖在上面，点它回到播放页。再打开播放页或者换一条视频，小窗重新出现。小窗里照样显示 JASSUB 画的 ass 字幕和 WebVTT 文字，文字按小窗宽度缩小。音频轨道从不显示小窗，切到音频时小窗消失。按钮都有 `aria-label`，小窗不抢焦点，也不困住焦点。
- **全屏和画中画**：标题右边有“画中画”和“全屏”两个按钮，浏览器不支持时不显示。全屏的是整个 Vidstack 元素，字幕画布和一条全屏控制栏（拖动、后退、播放、前进、画中画、退出全屏）跟着进入全屏，3 秒没有操作就隐藏。iPhone 的 Safari 没有元素全屏，Vidstack 改用视频自己的全屏，这时只有系统的控制栏，也看不到 JASSUB 的字幕。从视频切到音频轨道时自动退出全屏。
- **HLS**：Vidstack 设了 `preferNativeHLS`，能自己播 HLS 的浏览器（Safari、新版 Chrome）用原生播放，其他浏览器用打包进产物的 hls.js，不从 CDN 加载。打包的是 hls.js 的 light 版本，比完整版小三分之一。按 hls.js 1.7.3 的说明，它去掉了备用音轨、字幕轨、DRM、CMCD、变量替换、插播（interstitials）、I 帧快进、MediaCapabilities 探测，以及 MPEG-TS 里的 HEVC 和 AC-3。服务端生成的 HLS 只有一路 MPEG-TS 封装的 H.264 和 AAC，这些都用不到。以后服务端的 HLS 要用到其中任何一项，就要换回完整版。中途媒体 token 过期时，hls.js 的分片 401 会变成媒体错误，走播放流程第 3 步的恢复。Chromium 的原生 HLS 遇到分片 401 不报错，只会一直等数据，所以 HLS 来源等待超过 6 秒时，播放器重新 `GET` 一次元素加载的那个播放列表地址，之后每 6 秒再查一次：401 就换媒体 token、重新请求播放列表并回到原来的位置。409 `media_not_ready` 说明这一组 HLS 已被淘汰，播放列表返回 200 却指向另一组（设置来源时记下了原来那组的标识）说明它被淘汰后又重新生成过，这两种情况都带着上一次的 `force_fallback` 重新调用 `prepare`，每次加载最多两次。其他结果不处理。媒体错误时也用同样的检查。检查期间来源已经换过的话，晚到的结果直接丢掉。
- **字幕**：`subtitle_formats` 里有 `ass` 的视频，用 JASSUB 把 `subtitle?format=ass` 的原文画在视频上方，字体是 `/api/tracks/{id}/fonts` 列出的全部文件，URL 加上媒体 token 交给 JASSUB 的 worker。字体列表取不到时仍然渲染，用默认字体。没有 ass 字幕、或者 JASSUB 启动失败（worker 加载出错，或者 15 秒内没有就绪）时，视频底部显示当前这句 WebVTT 文字。字体地址里的媒体 token 可能已经过期，而 JASSUB 会悄悄忽略下载失败的字体，所以交给它之前先对第一个字体发 `HEAD`，401 就换一个新 token。视频没有字幕标签页，字幕直接显示在画面上。音频仍有 WebVTT 字幕列表。
- **回退字体**：JASSUB 自带的 Liberation Sans 没有中日文字形，作品不带字体时 ass 里的中日文会显示成方框，所以前端带两份回退字体。一份是 nixpkgs 的 Liberation Sans 2.1.5 Regular，覆盖原来 JASSUB 默认字体的全部字符，包括拉丁扩展、希腊和西里尔字母，去掉 hinting 后的 woff2 是 77444 字节。另一份是 Noto Sans CJK SC Regular 的子集，字符集是 ASCII、Latin-1、常用标点、CJK 标点、平假名和片假名、全角字符，加上 JIS X 0208 和 GB2312 能编码的全部字符，也就是第一、第二水准汉字和 6763 个简体汉字，映射了 10896 个字，woff2 是 1670668 字节（约 1.6 MB）。`nix/fallback-fonts.nix` 构建时用 fonttools 从 nixpkgs 的 liberation_ttf 和 noto-cjk 源码生成两份字体，仓库里不放字体文件。CJK 子集去掉了 `locl` 替换（否则会带上日、韩、繁体的全部异体字形，体积接近翻倍）和 hinting。日文汉字因此按简体中文的字形显示，比如“直”“骨”。JASSUB 的 FreeType 带 brotli，JASSUB 原来的默认字体就是 woff2，回退字体也用 woff2，CJK 子集比 otf（约 2.5 MB）小，在 Chromium 里实际渲染过。flake 把字体所在的目录通过 `KIKOERU_FALLBACK_FONTS_DIR` 交给 Vite 的 `$fallback-fonts` 别名，web 包和 `nix develop` 都设置了它，所以 `pnpm dev` 要在 `nix develop` 里运行。
- **回退字体怎么加载**：libass 只有一个默认字体族，缺字时从这个族里第一个有这个字的字体取字形。两份回退字体因此都改名为同一个族 `Kikoeru Fallback`（OFL 不许改过的 Liberation 继续用 Liberation 这个名字，独立的名字也让作品自带真正的 Liberation Sans 或 Noto Sans CJK 时 libass 不会错拿回退字体），并设为默认字体族。字幕要的字体作品没带、或者作品的字体缺某个字时，libass 才用它们，字幕点名而作品带了的字体始终优先。两份都是带哈希的独立文件，只有 JASSUB 为带 ass 字幕的视频启动之后，worker 才下载，音频和只有 WebVTT 的视频都不会请求。JASSUB 要等初始字体都下载完才就绪，就绪之前不显示字幕。拉丁回退字体很小，和作品字体一起作为初始字体加载，排在族里的第一位，所以两份都有的字（比如 ASCII）照旧用 Liberation Sans，和 Arial 等宽的排版也不变。CJK 子集在就绪之后再加进去，不拖慢作品字体和第一句字幕，下载完之前出现的中日文会短暂显示成方框。JASSUB 平时只在下一帧视频时重画，暂停时不会，所以 CJK 子集加好之后主动重画一次当前画面。服务器给它们一年的缓存，同一个版本只下载一次。
- **回退字体的许可**：Liberation Sans 和 Noto Sans CJK 都使用 SIL Open Font License 1.1。web 包里的 `licenses/fallback-font-latin.txt` 和 `licenses/fallback-font-cjk.txt`（服务器上在 `/licenses/` 下）是各自的版权声明和 OFL 全文，前面写着字体的来源和改动。换字体或改子集时，这两个文件要跟着换。
- **JASSUB 的文件**：worker、两份 WebAssembly（带 SIMD 和不带的）和两份回退字体都用 Vite 的 `?url` 导入，在产物里带哈希放在 `/_app/immutable/` 下。JASSUB 的代码只在第一次播放带 ass 字幕的视频时加载。JASSUB 自带的 `default.woff2` 由拉丁回退字体代替。JASSUB 的代码还用 `new URL(..., import.meta.url)` 引用了这个字体和 worker 自己的一份 WebAssembly，Vite 会给这两个文件各复制一份进产物，但它们不会被请求：设了 `defaultFont` 时 JASSUB 不加载默认字体，worker 也会把 `fetch` 换成加载传进去的 `wasmUrl`。所以 `web/src/lib/player/jassub-build.ts` 这个 Vite 插件在构建时改掉这两处引用，产物少了约 2.1 MB。JASSUB 升级后这两处代码要是变了，构建会失败，提醒检查插件。JASSUB 2.5.15 的 WebAssembly 和胶水代码不匹配，不能用。页面的 CSP 允许 `'wasm-unsafe-eval'`，见[部署](deployment.md)的“安全”。后端没有 COOP/COEP 头，JASSUB 因此用单线程模式。

## 代码结构

```text
web/src/
  lib/
    api/          调用后端的函数，类型由 ts-rs 生成，放在 api/types/
    player/       全局播放器状态、播放队列、进度上报、Vidstack 封装
    tasks/        任务进度流的跟踪、任务状态和扫描阶段的名字
    desktop/      认出桌面版外壳和页面种类、外壳命令、托盘的播放状态
    components/   封面卡片、封面网格、曲目树、状态图标等，admin/ 下是管理员用的部分，desktop/ 下是桌面版的设置
    stores/       当前用户、设置，以及设置页各栏的状态
  service-worker/           Service Worker，有自己的 tsconfig
  routes/
    +layout.svelte          根布局，挂载全局播放器和更新提示
    (fullscreen)/player/    全屏播放页
    (app)/library/
    (app)/search/
    (app)/favorites/
    (app)/recent/
    (app)/reviews/
    (app)/works/[id]/
    (app)/settings/
    login/
    desktop/                桌面版打包的选择页，只在外壳里出现
```

登录状态（API token、媒体 token、当前用户）放在 `stores/session.svelte.ts`，同时存进内存和 `localStorage`。读写 `localStorage` 都包在 `try/catch` 里，存储不可用时只在内存里保留。任何带 token 的请求收到 401 时，客户端清掉登录状态并跳回登录页。如果这个 401 来自已经被新登录替换掉的旧 token，就不清除新的登录状态。登录成功后马上换一个媒体 token 存起来，换失败不影响登录。每次存媒体 token 时同时写封面用的 cookie，打开页面时按存着的 token 补写一次，退出时删掉。桌面版本机模式的 401 先试一次外壳续签后存进 `localStorage` 的 token，见[桌面版](desktop.md)的“前端怎么用这些命令”。登录状态里另有一个 `account` 计数，登录和退出时加一，续签 token 时不变，根布局按它而不是 token 结束上一个账号的播放。

同一浏览器的其他标签页可能已经重新登录。登录时记录 API token 是否成功写入，写入失败时记住写入前的旧值。清理会话时，如果 `localStorage` 中的 API token 不为空，既不是当前标签页持有的 token，也不是本次写入失败前的旧值，就只清除当前标签页的内存状态，保留共享的 API token、媒体 token 和封面 cookie。写入失败留下的旧凭据仍要删除，不能当作其他标签页的新登录。旧标签页仍回到登录页，不自动接管另一个标签页的登录。存储不可用时仍清除本页状态和封面 cookie。

状态管理直接用 Svelte 5 的 runes（`$state`、`$derived`），不引入额外的状态库。服务端数据用一个简单的请求缓存，按 URL 缓存，收藏和进度变化时手动失效。缓存按登录会话区分：退出登录或换账号时整个清空，并丢弃旧会话发出、晚到的响应。

## 开发与假数据

在 `web/` 下用 `nix develop` 提供的 Node 22 和 pnpm：

| 命令 | 用途 |
|---|---|
| `pnpm gen:types` | 在仓库根目录运行 `neo-typegen`，把 API 类型生成到 `src/lib/api/types/` |
| `pnpm dev` | 开发服务器，`/api` 代理到本地后端 |
| `pnpm dev:mock` | 开发服务器，所有接口由 `contract/` 里的样本回答 |
| `pnpm check` | `svelte-check` 类型检查 |
| `pnpm test` | Vitest 单元测试 |
| `pnpm build` | 生产构建，输出到 `web/build` |

假数据模式由环境变量 `VITE_API_MOCK=1` 打开。客户端直接从仓库根目录的 `contract/` 导入样本，不复制，每个请求加 120 到 400 毫秒的延迟。登录时任意非空密码都会成功并返回 `login-response.json`，用户名 `setup` 返回 `setup_required`，用户名 `locked` 返回 `too_many_attempts`，方便检查登录页的错误提示。改密码时当前密码是 `wrong password` 返回 `invalid_credentials`，新密码不到 8 个字符返回 400，其他都返回 204，但假数据模式不保存密码，原来的 token 也不会失效。没有这个变量时，Vite 在构建时就把假数据分支去掉，生产产物里不包含样本。

API 类型全部由 `neo-typegen` 从 `neo-core::dto` 生成，每个类型一个文件，另有一个重新导出全部类型的 `index.ts`。这个目录被 `.gitignore` 忽略，不提交。`pnpm check`、`pnpm test` 和 `pnpm build` 都会先运行 `pnpm gen:types`，开发服务器不会。所以在新的检出里，先跑一次 `pnpm gen:types` 或其中任何一个命令，再启动 `pnpm dev:mock`。

查询参数不走 JSON，后端没有对应的 DTO，所以 `WorksQuery` 和排序类型写在 `web/src/lib/api/query.ts`，字段以[接口合同](contract.md)为准。除此之外，前端不定义任何 API 类型，全部从 `api/types/` 导入。

假数据模式也回答资料库接口：收藏、最近播放、标签、社团和声优列表都从 `contract/m3/` 的样本开始。收藏的切换和播放进度的变化只保存在内存里，重新加载页面就回到样本。样本以外的作品的轨道都当作已经探测过，没有时长的用 45 秒，和开发服务器生成的提示音一样长，所以它们的总时长能显示出来。样本作品 12 照合同样本保持“还没算出”，因为样本里有一条还没探测的 wav。为了让翻页、筛选和排序有东西可看，`web/src/lib/api/mock-catalog.ts` 在样本之后再生成 90 部“合成作品”，标签、声优、社团和媒体库按作品 ID 分配。另有 60 个“合成标签”和两个样本标签的另一种写法（耳語、全角的 ＡＳＭＲ），分到合成作品上，作品数按实际分到的算，让选择面板的搜索和“名字相近”有东西可看。搜索、筛选和排序的规则和合同一致。搜索 `503` 会返回 503 `storage_unavailable`，`云端作品` 媒体库里的作品（包括样本里的作品 13）在 `prepare` 时也返回这个错误，用来查看媒体库连不上时的提示。

假数据模式也回答播放和进度接口：作品详情、`prepare`、任务、进度、字幕、媒体库和扫描都用 `contract/m2/` 里的样本。样本以外的作品只有一个位置，在它所属的媒体库里，路径就是编号。`listener` 拿到的作品详情里 `locations` 是 `null`。路径以 `.wav` 结尾的轨道模拟需要转码的格式，`prepare` 先返回 `processing`，任务查两次 `running` 之后变成 `done`。媒体字节和封面不是 JSON，由开发服务器里的一个中间件（`web/src/lib/api/mock-media.ts`）回答：每条轨道生成一段 8 kHz 的单声道提示音 WAV，长度取样本里的时长，封面是一张 SVG。这些文件都在内存里生成，不提交进仓库，也不会进入生产构建。

假数据模式也回答管理接口，用的是 `contract/m4/` 的样本。任务列表从 `tasks-page.json` 的两条开始，前面再加 44 条已经结束的合成任务，各种状态都有，包括“已中断”，另有 6 条已完成的响度分析夹在中间，默认不列出。扫描由 `web/src/lib/api/mock-tasks.ts` 按时钟推进：排队半秒，发现作品 1 秒，同步轨道 4 秒，抓取元数据 2 秒，然后完成，同步轨道的计数按被扫描的那个媒体库的作品数算，和服务器一样。每个模拟扫描有自己的时钟，所以几个扫描会同时运行，排队中的也能移到最前，但移动只改变 `queue_position`，不改变开始的时间。同步轨道开始时再排上 5 个各 2 秒、一个接一个运行的后台探测，所以扫描完成后还能看到探测在跑。任务流是一个真正的 `text/event-stream` 响应体，和真实服务器一样经过同一个解析器。取消在 0.3 秒后生效。样本里正在运行的任务 121 没有时钟，一直停在样本的状态，取消后马上结束，它也不算正在运行的扫描，所以不会让清理返回 409。缺失列表和清理、标签合并、手动编辑和重新抓取都只改内存里的数据：清理掉的作品也会从收藏里消失，普通的重新抓取保留手动修改，强制的那种恢复样本的数据。手动修改过的作品在搜索、筛选和排序里也按修改后的数据处理。扫描完成后会多出一个“扫描发现的标签”，用来检查标签列表会不会重新读取。用户名 `listener` 登录一个不是管理员的账号，管理员接口对它返回 403。

假数据模式也回答媒体库管理接口：`GET /api/admin/roots` 从 `contract/m7/roots.json` 和 `contract/webdav/roots.json` 开始，`本地作品` 写在配置文件里，`云端作品`（OpenList）和 `NAS`（WebDAV）在数据库里并保存了密码。添加、修改和删除只改内存里的数据，校验和错误码与合同一致：重复的 ID 返回 409 `root_exists`，配置里的媒体库返回 409 `root_read_only`，正在扫描时删除、或者改路径、地址、目录和用户名返回 409 `scan_running`，换了协议、主机或端口却没填密码、密码带换行和路径 `/srv/media/不存在` 返回 400。OpenList 或 WebDAV 的主机名里有 `unreachable` 时检查返回 503 `storage_unavailable`，密码是 `wrong password` 时返回 502 `upstream_error`，带上 `skip_check` 就照样保存。删除之后这个媒体库里的作品出现在缺失列表里。样本里 `本地作品` 每天自动扫描并且正在监视，`云端作品` 每 6 小时自动扫描。保存的媒体库按设置报告 `next_scan_at`（现在加上间隔）和 `watching`（本地并且开了监视），超出间隔范围或者给 OpenList、WebDAV 开监视返回 400。换成另一种服务却没填密码也返回 400。收到的添加和修改请求记在 `window.__kikoeruMockRootRequests` 里给测试检查，密码换成 `<redacted>`。规则在 `web/src/lib/api/mock-roots.ts`。

假数据模式的服务器设置从没有代理开始，`PUT` 按合同的规则检查和整理代理地址，不合规则时返回 400。测试连接总是回答 200 和 380 毫秒，代理的主机是 `unreachable.test` 时返回 502 `upstream_error`。规则在 `web/src/lib/api/mock-settings.ts`。

假数据模式也回答视频接口：样本作品 12 多了一个 `映像` 目录，里面是 `contract/m6/track-video.json` 的 `本編.mkv`（要先等 HLS 任务，完成后用 `task-done-hls.json`）、一个直接播放的 `予告.mp4`，以及 `fonts.json` 列出的两个字体文件。`subtitle?format=ass` 返回一段 ass，每句两行，第一行是拉丁字母，末尾带几个只有 Liberation Sans 才有的波兰、希腊和乌克兰字母，第二行是日文和简体中文，`fonts` 返回字体样本。开发服务器的中间件第一次被请求视频时用 ffmpeg 生成一段 60 秒的 mp4 和一组 6 秒分片的 HLS，画面下半部分是纯黑的，字体文件用 JASSUB 自带的字体。所以 `pnpm dev:mock` 播放视频需要 `nix develop` 里的 ffmpeg。媒体 token 每换一次都不同，测试可以让旧的那个失效。

浏览器测试按行为和测试文件集中记录在[测试与验证](testing.md#浏览器测试)，包括生产包集成与假数据交互。错误响应使用生成的 `ErrorResponse`，客户端的 `ApiError` 另有用于网络失败等情形的本地错误码。

## PWA

PWA 与普通浏览器共用前端，后台播放和锁屏控制需要分别验证浏览器标签页与添加到主屏幕后的行为。

- manifest 是 `web/static/manifest.webmanifest`，设置 `display: standalone`、图标和主题色，`start_url` 是 `/library`。图标是 `static/favicon.svg` 里由声波组成的 K，由 `web/scripts/make-icons.mjs` 画成 192 和 512 像素的 PNG，另有一张 maskable 图标和 iOS 用的 `apple-touch-icon`。改了图标就重新运行这个脚本，生成的 PNG 只有几 KB，直接提交。
- Service Worker 用 SvelteKit 自带的支持（`src/service-worker/`），不用 `@vite-pwa/sveltekit`。后者只支持 SvelteKit 1 和 2，在 SvelteKit 3 的构建里不会生成 Service Worker。
- Service Worker 只缓存前端自己的文件：构建产物、`static/` 和 `index.html`。JASSUB 的两份 WebAssembly 各约 2 MB，两份回退字体共约 1.7 MB，只有带 ass 字幕的视频才用，所以和产物里的其他 woff2（界面用系统字体，woff2 都属于 JASSUB）一样不在安装时预先缓存，第一次用到时照常从服务器取。页面导航一律返回缓存的 `index.html`，构建产物优先读缓存。新版本接管时保留上一个版本的缓存，更早的才删掉，因为没有刷新的标签页还在运行旧代码，可能还要加载旧版本的脚本块，而服务器上已经没有这些文件了。`/api` 下的请求，包括 API 响应、封面和音频，都不经过缓存。
- 新版本的 Service Worker 装好之后不自动接管，页面提示“有新版本可用”。用户点“刷新”才让它接管并重新加载，点“稍后”就继续用旧版本，避免打断正在播放的音频。开着几个标签页时，在一个标签页里点“刷新”会让新版本接管所有标签页，但只有点了的那个会重新加载，其他标签页继续播放。之后在其他标签页里再点“刷新”，就直接重新加载。为了能做这个提示，自动注册关掉了，由 `UpdatePrompt.svelte` 注册。开发服务器上不注册，缓存的页面会挡住开发中的改动。

## 纯 HTTP 访问

纯 HTTP 是支持的访问方式。例如可通过 `http://media.example.lan:8888` 访问没有配置 HTTPS 的测试服务。浏览器把这种地址算作不安全的上下文，只有 `localhost`、`127.0.0.0/8` 和 `::1` 例外，并且在不安全的上下文里收回一部分 API。在纯 HTTP 下，登录、浏览、搜索、收藏、音频和视频播放（包括 HLS 和 JASSUB 画的 ass 字幕）、进度上报、锁屏和耳机控制，以及设置页和管理功能都必须照常工作。

只有安装成应用和离线打开要求 HTTPS：

- Service Worker 只在安全上下文里提供，纯 HTTP 下 `navigator` 上没有 `serviceWorker`。`UpdatePrompt.svelte` 发现没有它就不注册，所以没有离线缓存，也没有“有新版本可用”的提示。页面每次从服务器加载，`/_app/immutable/` 的长缓存照常生效。
- 没有 Service Worker，Chrome 不提供安装。manifest 仍然在页面里，不报错。
- 设置页在不安全的上下文里显示一条“通过 HTTP 访问”的说明（`PlainHttpNote.svelte`），写明哪些功能照常可用，以及安装和离线要改用 HTTPS 地址。

前端代码不依赖只在安全上下文里才有的 API：

- 不用 `crypto.randomUUID`、`crypto.subtle`、`navigator.clipboard`、`navigator.storage`、Cache API 和 `SharedArrayBuffer`。hls.js 里的 `crypto.randomUUID` 包在 `try` 里，失败时有回退。它的 `crypto.subtle` 只用来解密加密的 HLS，而服务端生成的 HLS 不加密。
- `localStorage` 和 Media Session 在纯 HTTP 下都能用，锁屏控制不受影响。
- JASSUB 读取本机字体要用 `queryLocalFonts`，Chromium 只在安全上下文里提供它，其他浏览器根本没有。`secure-context.ts` 的 `localFontQuery()` 在没有这个函数时关掉 JASSUB 的本机字体查找。否则 Firefox 和 Safari 会因为不认识 `local-fonts` 权限而抛出 TypeError，每缺一个字体就在控制台留一条警告。JASSUB 的 Worker 和 WebAssembly 不需要安全上下文，`crossOriginIsolated` 为假时它只用一个线程渲染。
- 以后的代码要用只在安全上下文里才有的 API 时，先检查它存不存在，没有就退回到不用它的做法，并且让[测试与验证](testing.md)里的 `insecure` 端到端项目覆盖到。

后端不区分 HTTP 和 HTTPS。它不主动设置 cookie。API token 走 `Authorization` 头，媒体请求接受查询参数中的媒体 token，封面还接受前端设置的媒体 cookie，见[认证与用户](auth.md)。它也不发 HSTS，不把请求跳转到 HTTPS。媒体地址、HLS 播放列表和分片的地址都是相对路径，不依赖 `public_url`。部署时的 HTTP 与 HTTPS 配置见[安全与网络指南](https://github.com/QWERChin/kikoeru-neo/blob/main/docs/zh-CN/security.md)。

## 无障碍

- 所有图标按钮都有 `aria-label`。
- 可点击的元素都用 `button` 或 `a`，不用带点击事件的 `div`。
- 点击区域至少 44×44 像素。
- 文字和背景的对比度至少 4.5:1。
