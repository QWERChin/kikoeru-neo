# 路线图

服务器、网页与 PWA、本地和远端媒体库、迁移、备份、视频、响度与波形，以及桌面应用外壳均已实现。本页只记录尚未完成的工作，按领域列出问题、触发条件和状态。当前测试覆盖及平台缺口见[测试与验证](testing.md)。

## 播放与字幕

- [ ] 媒体 token 续签遇到网络切换或代理 502 时，`prepare.ts` 的 `refresh-token` 分支直接报错，音频不能自动等连接恢复。状态：待修复，当前需手动重试。
- [ ] HLS 设置来源时获取组号失败，之后旧组被淘汰并生成新组，播放列表返回 200、旧分片返回 409 时，停顿检查无法识别换组，可能误走强制转码。状态：待修复组号获取与恢复流程。
- [ ] 波形 URL 不带来源版本。文件替换并重新扫描后，浏览器在一周缓存有效期内仍可能显示旧波形。状态：待修改合同、缓存版本和前端地址。
- [ ] 播放器实例未更换时，同一轨道的源文件被替换后再次播放，内存中的旧波形不会清除或重取。状态：待修复播放器缓存失效。
- [ ] ASS 转 WebVTT 仅去掉控制块，绘图模式 `\p1` 中的路径会变成字幕正文。状态：待跟踪绘图模式并丢弃去除绘图后为空的事件。

## 扫描与元数据

- [ ] 扫描摘要与日志只保存在任务表。部分作品的文件树列出失败时，设置页仍只显示完成，无法看到失败数和原因。状态：待定义扫描任务的结果合同并接入页面。
- [x] 作品子目录列举失败时，扫描仍同步可读目录，失败路径及其后代的轨道保持原样，既不标缺失也不计作见到，并记录失败路径和原因。部分遍历保存与来源迁移不同的重遍历标记并清空完整列举标记，既等待完整列举后再补匹配进度，也不反复排队未变化文件的失败探测，扫描、存储和数据模型说明已同步更新。
- [x] OpenList 和 WebDAV 成功返回空根目录时，现与本地媒体库一样按不可用处理，扫描失败并说明原因，已有的位置、作品和轨道保持不变。空子目录仍正常同步，存储和扫描合同已同步更新。
- [ ] 更新封面后，旧版本缩略图留在磁盘。状态：待实现与并发缩略图生成协调的清理，防止清理后旧版本又写回。
- [ ] DLsite 社团名本身含方括号时，按最后一个 ` [` 去后缀可能留下半个社团名，例如 `作品 [Circle [Label]] | DLsite`。状态：待核实来源是否会返回这种结构，再决定按 `maker_name` 匹配完整后缀。

## 调度、存储与停服

- [ ] PostgreSQL 入队事务已提交但提交确认丢失时，`submit` 可能返回失败而没有登记运行器，后续去重取得的任务会一直排队直到重启。状态：待处理提交结果不确定时的任务恢复。
- [ ] 读取状态与生成快照之间，排队扫描恰好开始时，任务列表、单任务查询或 SSE 首个事件可能返回没有队列位置的排队快照。状态：待统一状态和位置的读取时点。
- [x] 远端媒体库的地址和密码版本引用现在在同一数据库事务中提交，旧密码文件不再被覆盖。回收只删除本服务拥有且无人引用的版本，保护配置路径及其别名，PostgreSQL 回收还等待旧媒体库事务结束后读取引用。
- [x] 提交确认丢失后的媒体库更新重试同时比较已提交设置与当前客户端的位置，任一位置变化都执行扫描互斥并清除来源缓存。回归测试覆盖旧客户端扫描后重试更新，再普通扫描发现新来源深层轨道。
- [x] 停服先关闭媒体库修改准入，后台清理等待已接收的修改结束后才关闭数据库并释放实例锁。并发测试验证了等待 `secrets/.lock` 的修改超过停服期限时，新实例仍不能启动。
- [ ] 本地媒体库开启 `watch` 且位于失联的 NFS 或 FUSE 挂载上时，递归监听初始化会阻塞，可能超过停服期限。状态：待隔离无法取消的文件系统调用。
- [ ] 正在播放或生成的缓存条目本身超过 `cache.max_bytes` 时，淘汰会跳过它们，直到下一次生成才再次清理。状态：待设计串行淘汰和新结果保护期，不能在首次播放前立刻删掉刚生成的结果。

## 界面与会话

- [ ] 设置页完整扫描的标签仍声称会刷新网盘缓存，说明也只提 OpenList，使用 WebDAV 或等待远端目录刷新时会误导读者。状态：文档已说明实际行为，界面文字待同步。
- [ ] 旧标签页处理 401 时，读取和删除存储中的 token 之间，另一标签页恰好写入新 token，会把新登录一起清掉。状态：待修复跨标签页的会话清理竞争。
- [ ] 选择器搜索高亮在小写转换改变名称长度时可能错一位，例如在 `İris ASMR` 中搜索 `asmr`。状态：待修复 `web/src/lib/list-picker.ts` 的 `highlight`，保留归一化文本到原名称的索引对应关系。

## 导入与桌面应用

- [ ] `--map-path` 使用相对 Windows 前缀时，`Media/Audio` 可能匹配不到旧配置的 `Media\Audio`。Windows 前缀比较也只忽略 ASCII 大小写，`C:\MÜSIC` 与 `c:\müsic` 不匹配。状态：待修复路径映射，当前表现为媒体库找不到，不会写入错误位置。
- [ ] `migrate --yes --root` 写错旧媒体库名时不报错，而是使用默认生成的 ID。状态：待验证全部显式映射均被消费。
- [ ] 桌面导入时，大小写不同但指向同一 Windows 目录的路径会被添加为两个媒体库。状态：待统一目录比较规则。
- [ ] 桌面导入等待确认推测路径时，点“重新选择”后取消对话框，会清掉原选择和确认项。状态：待保留取消前的表单状态。
- [ ] 桌面本机页面换用续签 token 时，元数据代理栏的加载副作用会重新取设置，覆盖未保存输入。状态：待限制重新加载的触发条件。
- [ ] macOS 叠加标题栏下，选择页、登录页和错误页在宽窗口整页滚动时，内容会滑到透明拖动条下方。状态：待把滚动区域限制在标题栏下面。
- [ ] macOS 和 Windows 安装包尚需逐项验证后台播放、媒体键、休眠、WebView 媒体能力和两种模式。状态：构建与部分自动检查已具备，真机验证未完成，Linux 尽力支持。
- [ ] 分发桌面安装包时仍会遇到未签名提示。状态：签名、公证与证书管理方案待定，见[设计决定与开放问题](open-questions.md)。
- [ ] 桌面应用没有自动更新流程。状态：待设计更新发布、签名和失败恢复机制。
- [ ] Linux 桌面版经 tauri 的 GTK3 依赖锁定 `glib` 0.18.5，受 GHSA-wrw7-89jp-8q8g（`VariantStrIter` 的空指针崩溃）影响。我们的代码和 wry、tao、webkit2gtk、gtk 都不调用这个类型，Dependabot 告警已按“代码未使用”驳回。修复要求 `glib` 0.20，而 GTK3 绑定已停止维护。状态：tauri 换到 GTK4 后升级并复查。

## 验证与资源测量

- [x] 首个 `v0.1.0` 发布：GHCR 镜像可匿名拉取，GitHub Release 的静态资产下载后校验通过，并在 Alpine 容器里启动成功。快速开始的 Docker 命令用发布镜像完整跑通。
- [ ] 根 Dockerfile 和 Dev Container 需要在原生 aarch64 主机及 VS Code、JetBrains 中验证。状态：x86_64 的真实 Docker 主机上两者都已构建并通过冒烟，Ubuntu CI 在相关输入变化时重复这项检查。
- [x] 发布工作流已改为确认标签属于 `main` 历史，并复用最近的主线 CI 成功结果，仅允许其后存在符合 CI 忽略规则的文件差异，不再在一个 runner 上重新构建全部检查。门禁通过临时 Git 仓库和假 API 测试验证，但 `v0.1.0` 和 `v0.1.1` 首次发布的 e2e 失败原因仍未确认。
- [x] 分配器比较：glibc、jemalloc、mimalloc 和 musl mallocng 在同一合成负载下各测一小时，静态包据此改用 jemalloc，glibc 构建保留 `MALLOC_ARENA_MAX=2`。见[测试与验证](testing.md#分配器测量)。
- [ ] glibc 默认 malloc 在远端播放下每小时约 12 MiB 的 RSS 增长没有在一小时合成浸泡中复现。状态：要重新证明 `MALLOC_ARENA_MAX=2` 的必要性，需要更长的运行或更接近实际的远端负载。
- [x] `scripts/soak.py` 对没有时长的强制转码轨道已按服务端 AAC 输出的 192 kbit/s 控制读取节奏。
- [ ] 假数据浏览器测试缺少可比较的资源测量。状态：待用 `scripts/check-memory.py e2e-mock` 在可控负载下记录峰值和用时。
- [ ] PostgreSQL 测试在高负载下的连接池超时缺少稳定复现。状态：待在合成环境保留连接池等待与资源压力证据，不能直接归因于产品逻辑。
- [x] `neo-scanner` 的 `hvdb_requests_are_spaced_and_follow_no_redirect` 已改用 Tokio 暂停时钟和在网络 I/O 前立即失败的请求，按 200 毫秒间隔精确断言重试与连续查询的累计耗时，不再受假服务器接收延迟影响。已用受控接收延迟复现原误报并验证修正，临时移除限流后新测试仍会失败。
- [ ] 登录媒体凭据交换失败后的页面导航用例可能在高负载下超时。状态：待稳定复现并保留 trace，区分导航缓慢与登录未完成，不能靠放宽断言判定已修复。
- [ ] Android 和 iOS 真机上的后台播放、锁屏界面、耳机按钮与声音输出未完成系统验证。状态：待按[手机播放验证](testing.md#手机播放验证)执行，模拟器结果不替代这些项目。
