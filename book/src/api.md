# API 设计

API 把资料库查询、用户状态、媒体读取和后台任务分开。所有接口都在 `/api` 下，不兼容旧 kikoeru 的接口。请求字段、响应字段、默认值、错误码和权限的唯一参考是[接口合同](contract.md)，本章只解释设计与调用流程。

## 类型与边界

业务接口返回 JSON，媒体接口返回字节流，任务事件使用 SSE。公开类型定义在 `neo-core::dto`，由 ts-rs 生成前端 TypeScript 类型。数据库行类型不能直接序列化为 API 响应，密码哈希和原始路径等内部字段不越过这条边界。

字段和合成样本一起维护，合同测试比较完整 JSON 值，类型检查使用实际生成的 TypeScript。通用的 ID、时间、分页、空值和错误规则见[合同的通用规则](contract.md#通用规则)。

## 认证与用户状态

登录取得 API token，普通 API 请求用它鉴权。播放前换取媒体 token，供不能设置认证头的媒体元素使用，封面另支持由前端设置的媒体 cookie。两类凭据的权限不同，详见[认证与用户](auth.md)。

作品列表直接包含当前用户的收藏、评分和进度摘要，避免每张卡片再单独查询。作品详情提供扁平轨道列表，前端按显示路径重建曲目树。字段名以合同中的 `WorkSummary`、`WorkDetail` 和 `TrackItem` 为准。

进度更新必须允许向后拖动，不能简单保留最大播放位置。同一会话内的报告使用递增序号拒绝晚到的旧报告，不建立不同设备之间的全局顺序。清除与完成操作的边界见[进度接口](contract.md#put-apimeprogresswork_id)和[数据模型](data-model.md#进度报告的会话序号)。

## 先准备，再播放

1. 浏览器检测可播放的 MIME 类型，按合同中的 `PrepareRequest` 调用准备接口。
2. 后端结合轨道探测结果决定直接播放、使用已有缓存，或提交转码任务。探测尚未完成时先做有超时的探测。
3. 准备完成的响应给出地址和 MIME 类型。需要等待时，前端轮询返回的任务，结束后读取任务结果。
4. 播放器只有拿到可用结果后才设置媒体源。直接播放失败时重新提交完整的准备请求并要求回退，音频回退为 AAC，视频回退为 HLS。

请求与响应的字段定义见 [`PrepareRequest`](contract.md#preparerequest)、[`PrepareResponse`](contract.md#prepareresponse)及[视频准备](contract.md#视频的-prepare)。准备接口不接受客户端给出的 ffmpeg 参数或外部 URL。

原始媒体接口不转换文件，可播放媒体接口只返回已经准备好的结果，不在读取时暗中创建任务。媒体的 HEAD 请求只返回已有信息，不触发探测或转码。响度和波形是另行触发分析的 GET 接口，不支持 HEAD。Range、HLS 分片、字幕和字体的规则见[媒体合同](contract.md#播放与媒体)与[媒体处理与播放](media.md)。

## 远端读取与下载

本地文件经存储层打开，远端文件由后端代理。OpenList 的凭据和直链不交给浏览器。上游认证失败与本服务登录失效必须区分，不能把远端的 401 原样当作用户会话过期。转发头和错误分类见[存储后端](storage.md)。

作品和目录下载使用边读边写的 ZIP64 流，不压缩文件，不支持断点续传。重复副本不打入压缩包，路径冲突的条目改名。远端文件逐个读取。所有用户合计最多同时进行 2 个打包下载，再多的请求返回 429 `queue_full`，见[接口合同](contract.md#媒体字节)。下载失败需要重新发起，不能在已经发送的字节后追加 JSON 错误。

## 管理与任务

媒体库管理、扫描、元数据编辑和缺失清理都要求管理员身份。配置文件中的媒体库不能通过 API 修改。扫描先入队，再由任务接口报告状态，完整扫描只关闭远端目录摘要跳过，不强制刷新 OpenList 的目录缓存。

任务由调度器持有，发起请求的浏览器断开不取消任务。普通用户可以查询自己触发的转码和分析任务，管理任务、任务列表和 SSE 受管理员权限限制，详见[任务合同](contract.md#任务)。

前端用带认证头的 `fetch` 读取 SSE，不使用不能设置该头的标准 `EventSource`。重新连接先取得当前快照，订阅失败时可以改用轮询。取消必须显式调用取消接口，断开事件流只结束订阅。

缺失清理是不可撤销的物理删除，和扫描中仅标记缺失是不同的操作。调用前需明确选中的作品或位置及其用户状态影响，不能把暂时无法连接的媒体库当作空库清理。
